# 架构迁移设计

状态：拟议设计，需在每阶段用依赖与行为测试验证。需求见 [spec.md](spec.md)，执行顺序见 [plan.md](plan.md)。

## 目标依赖方向

```text
CLI / LSP / 宿主组合根
          ↓
解释后端    IL 后端    字节码编译与 VM
      ↘       ↓       ↙
       共享语法模型 / 解析器 / 必要运行时契约
                    ↓
                  Core
```

箭头表示编译期依赖，而非调用顺序。模块抽象由需要它的层引用，官方模块和其他发行版依赖由组合根注册；共享并发、观测与项目系统仅在确有需要时引用。以上是目标职责图，项目名称及颗粒度应在消除循环依赖后确定，不能用对 Runtime 的反向引用伪造独立后端。

## 语法与运行时分界

AST 负责源位置、语法数据和遍历分派；解释求值、IL 发射、类型推断及字节码生成属于各自处理器。现有 `LangValueType` 既是表达式又承载运行时对象、运算和模块行为，不能简单整体搬到语法程序集。先盘点构造与使用方，区分字面量语法节点和执行值，再逐步引入明确的边界与转换；保持现有对象身份、闭包、可变集合和错误位置语义。

生成的 `IVisitor` 当前引用大量运行时值类型；拆分之前调整生成器及接口，使其表达可独立编译的语法节点。节点执行方法的调用、重写和 Visitor 回调应按节点族逐步替换；中途兼容转发必须防止 `Accept → Run → Accept` 递归。完成迁移后移除兼容方法，而不是永久保留依赖后端的基类。

## 后端与组合

解释后端拥有作用域、控制流、模块执行及异步/生成器状态；IL 后端拥有 `LocalManager`、IL 发射、类型推断及编译期依赖；VM 拥有字节码编译、指令与执行状态。先审计运行时值、反射、模块和扩展方法的跨后端依赖，再抽出最小共享契约；不以将整个解释器作为 IL 或 VM 的隐式共享层为终态。编译期预执行声明等现有依赖必须显式建模并由集成测试覆盖。

`Old8HostBuilder` 是组合入口。模块目录随宿主及其创建的执行上下文传递；保留的默认目录仅能作为明确记录的兼容边界，最终应由依赖搜索和隔离测试决定是否移除。官方扩展程序集只由官方组合层引用。

## 迁移与风险控制

按节点族迁移，先建立行为基线，再移动实现、替换调用并测试解释/IL/VM 的相关路径；生成器恢复、异常控制流、导入顺序和函数调用栈是高风险点。对公开 C# API 的变更提供迁移说明。历史字节码格式在迁移前后用固定样本及读写执行测试验证；若发现格式必须变化，先明确版本和兼容策略。

程序集边界测试检查实际引用图，行为测试检查结果、副作用和错误，二者缺一不可。每次节点迁移避免直接启用尚未与旧路径等价的 Visitor 分支；先用测试验证短路、作用域清理、返回值丢弃和异常传播。
