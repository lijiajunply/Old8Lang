# 阶段 2「函数声明语法迁移」测试报告

日期：2026-11-14 15:02
范围：`Docs/architecture-migration/plan.md` §2 的增量：函数/异步函数声明的语法/运行时边界
状态：本批完成；阶段 2 整体未完成（类声明、Import/Native、LinqExpression、解析器整体仍待拆分）。

## 1. 本批改动

| 变化 | 说明 |
|------|------|
| `FunctionSyntax`（Syntax） | 函数声明的纯语法模型：函数名/返回类型注解、参数、函数体、泛型参数、装饰器、文档注释、是否 async |
| `FuncInit`/`AsyncFuncInit`（Syntax） | 从 Runtime 迁入 Syntax，构造函数改为接收 `FunctionSyntax`；保留 `Id`/`Parameters`/`Body`/`IsLambda`/`ValidateParamsParameter` 等语法视图 |
| 运行时适配 | `FunctionSyntaxRuntimeFactory` 创建原 `FuncLangValue`/`AsyncFuncLangValue` 并复制装饰器/文档注释；`GetFuncValue()`/`GetAsyncFuncValue()` 用 `ConditionalWeakTable` 按语法节点缓存，保持原对象身份 |
| 解析器 | `FunctionParser` 不再直接构造运行时函数值，只构造 `FunctionSyntax`；extern 签名也改用语法模型 |
| 消费者更新 | 解释器/编译器/字节码 Visitor、IL 全程分析与 VM 闭包分析、类型推断/约束收集、LSP、ext 提供器与测试改用语法字段或 `GetFuncValue()` |
| IL 全程分析 | `GlobalVariableAnalysis.CollectFunctionReferences` 识别 `FuncInit`/`AsyncFuncInit` 的语法函数体，恢复顶层变量提升 |
| partial 清理 | `FuncInit.Split.cs`/`AsyncFuncInit.Split.cs` 转为 Runtime 扩展类；重复的 `GetItemType` 改用既有 `FuncLangValue.GetItemType` |
| 生成代码 | Runtime 节点 57 → 55，遗留 partial 基线 11 → 9 |

## 2. 迁移中暴露并修复的问题

首次回归发现 5 个 IL 顶层变量用例（`NamedFunction_ReadsTopLevelVariable` 等）与
`LoopVariable_DoesNotOverwriteTopLevelVariable` 失败：顶层变量分析原先通过 AST 中的
`FuncLangValue` 节点收集函数体引用，节点改为 `FunctionSyntax` 后不再触发。为 `FuncInit`/
`AsyncFuncInit` 增加语法体收集分支后，失败数与失败用例回到基线。
