# 实现类型假注的运行时类型检查

## 目标
在解释模式下，当变量有类型注解（如 `a:int`）时，每次赋值都需要进行类型检查，如果类型不匹配则报运行时错误。

## 实现思路
1. 在 `SetStatement.Run` 方法中添加类型检查逻辑
2. 建立类型注解与值类型的映射关系
3. 当类型不匹配时抛出类型错误

## 实现步骤

### 1. 分析类型映射关系
- 类型注解格式：小写字符串，如 "int"、"double"、"string"、"bool"、"char"
- 值类型 `TypeToString()` 返回：首字母大写字符串，如 "Int"、"Double"、"String"、"Bool"、"Char"

### 2. 修改 `SetStatement.Run` 方法
在赋值前检查类型注解，如果存在则验证值类型是否匹配：

```csharp
public override void Run(VariateManager manager)
{
    var result = Value.Run(manager);
    
    // 如果有类型注解，进行类型检查
    if (!string.IsNullOrEmpty(Id.AssumptionType))
    {
        var expectedType = Id.AssumptionType.ToLower();
        var actualType = result.TypeToString().ToLower();
        
        // 建立类型匹配映射
        var typeMap = new Dictionary<string, List<string>>
        {
            { "int", ["int"] },
            { "double", ["double"] },
            { "string", ["string"] },
            { "bool", ["bool"] },
            { "char", ["char"] }
        };
        
        // 检查类型是否匹配
        if (typeMap.TryGetValue(expectedType, out var allowedTypes))
        {
            if (!allowedTypes.Contains(actualType))
            {
                throw new TypeError(Id, expectedType, actualType);
            }
        }
    }
    
    manager.Set(Id, result);
}
```

### 3. 创建 TypeError 异常类
如果不存在，则需要创建一个 `TypeError` 异常类来处理类型不匹配的情况。

### 4. 测试类型检查
- 测试合法赋值：`a:int <- 123` 应该成功
- 测试非法赋值：`a:int <- "hello"` 应该抛出类型错误

## 实现关键点
- 类型注解的大小写处理
- 准确的类型映射关系
- 清晰的错误信息
- 不影响无类型注解的变量赋值

## 预期效果
- 当变量有类型注解时，每次赋值都会检查类型
- 类型不匹配时抛出明确的类型错误
- 无类型注解的变量不受影响
- 解释模式下正常工作
