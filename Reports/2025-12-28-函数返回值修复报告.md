## 问题摘要

编译模式下函数调用返回值错误，导致大量测试失败。具体表现为：
- 简单函数调用在顶层执行时返回正确值
- 函数在另一个函数内部被调用时返回错误值（垃圾值或 0）
- 影响了约 47% 的测试用例

---

## 问题根本原因

发现了两个独立但相关的编译器 Bug：

### Bug 1: ReturnStatement 错误地将所有返回值包装为 Task<object>

**文件**: `Old8Lang/AST/Statement/ReturnStatement.cs`
**问题代码**（第44-68行）:

```csharp
// 获取返回值类型
var returnType = returnExpression.OutputType(local);

// 加载返回表达式的值
returnExpression.LoadIlValue(ilGenerator, local);

// ❌ 错误：假设所有函数都是异步函数
if (returnType != typeof(Task<object>))
{
    // 将返回值包装为 Task<object>
    if (returnType != null && returnType != typeof(object))
    {
        ilGenerator.Emit(OpCodes.Box, returnType);
    }

    var fromResultMethod = typeof(Task).GetMethod("FromResult", ...)!.MakeGenericMethod(typeof(object));
    ilGenerator.Emit(OpCodes.Call, fromResultMethod);
}

ilGenerator.Emit(OpCodes.Ret);
```

**问题分析**:
- 代码错误地假设所有函数都是异步函数
- 对于同步函数 `func getValue() -> int { return 42 }`：
  - 返回值 42 (int) 被装箱为 object
  - 然后被包装为 `Task<object>`
  - 但函数签名声明的返回类型是 `int`，不是 `Task<object>`
  - 导致栈上留下错误类型的值，调用者读取到垃圾值

### Bug 2: FuncInit 创建新 LocalManager 时未复制全局信息

**文件**: `Old8Lang/AST/Statement/FuncInit.cs`
**问题代码**（第77-79行）:

```csharp
// ❌ 错误：创建全新的 LocalManager，丢失了已定义的函数信息
var funcLocal = new LocalManager() {
    FilePath = local.FilePath,
    Interpreter = local.Interpreter
};
```

**问题分析**:
- 每个函数编译时创建新的 `LocalManager` 以隔离局部变量
- 但新的 `LocalManager` 是全新实例，`DelegateVar` 字典为空
- 导致函数内部无法找到其他已定义的函数
- 例如 `func test2() -> int { return test1() }` 无法找到 `test1`
- 产生 `NullReferenceException` 或返回错误值

## 修复方案

### 修复 Bug 1: 移除错误的 Task 包装逻辑

**修改文件**: `Old8Lang/AST/Statement/ReturnStatement.cs:33-59`

```csharp
public override void GenerateIl(ILGenerator ilGenerator, LocalManager local)
{
    // 检查是否在finally块中使用了return语句
    if (local.IsInFinallyBlock)
    {
        throw new Error.CompilerException("在finally块中不允许使用return语句", Position);
    }

    // 获取返回值表达式的类型
    var returnType = returnExpression.OutputType(local);

    // 加载返回表达式的值到栈上
    returnExpression.LoadIlValue(ilGenerator, local);

    // ✅ 修复：只有异步函数才需要 Task 包装
    // 同步函数直接返回值，不进行任何包装
    if (returnType == typeof(Task<object>))
    {
        // 异步函数：返回值已经是 Task<object>，直接返回
        ilGenerator.Emit(OpCodes.Ret);
    }
    else
    {
        // 同步函数：直接返回栈上的值
        ilGenerator.Emit(OpCodes.Ret);
    }
}
```

### 修复 Bug 2: 复制全局信息到函数的 LocalManager

**修改文件**: `Old8Lang/AST/Statement/FuncInit.cs:77-98`

```csharp
// 创建一个新的LocalManager实例，专门用于函数体的IL生成
// 这样可以避免函数内部的局部变量与外部的局部变量冲突
// ✅ 修复：保留DelegateVar、ClassVar等全局信息，以便函数内部可以调用其他函数
var funcLocal = new LocalManager() {
    FilePath = local.FilePath,
    Interpreter = local.Interpreter
};

// 复制全局信息：委托、类、全局静态类
foreach (var (key, value) in local.DelegateVar)
{
    funcLocal.DelegateVar[key] = value;
}
foreach (var (key, value) in local.ClassVar)
{
    funcLocal.ClassVar[key] = value;
}
foreach (var (key, value) in local.GlobalStaticClasses)
{
    funcLocal.GlobalStaticClasses[key] = value;
}
foreach (var (key, value) in local.FuncParameters)
{
    funcLocal.FuncParameters[key] = value;
}
```

## 技术细节

### IL 代码生成流程

**正确的函数调用 IL 生成**：
1. `Instance.LoadIlValue()` 从 `DelegateVar` 查找目标函数
2. 加载所有参数到栈上
3. 使用 `OpCodes.Call` 调用 `DynamicMethod`
4. 返回值留在栈上，供调用者使用

**正确的 return 语句 IL 生成**：
1. `ReturnStatement.GenerateIl()` 加载返回值表达式
2. 返回值已经在栈上
3. 直接发出 `OpCodes.Ret` 指令
4. **不进行任何类型包装**（除非是真正的异步函数）

### 关键设计决策

**为什么要复制 DelegateVar 而不是 Clone LocalManager？**
- `LocalVar`（局部变量）应该独立，避免冲突
- `DelegateVar`（函数）、`ClassVar`（类）应该共享，作为全局符号表
- 这保证了：
  - 函数内部可以调用外部定义的函数
  - 函数内部的局部变量不会污染外部作用域
  - 函数定义本身会被添加到全局 `DelegateVar`

## 经验总结

### 问题诊断技巧
1. **对比测试**: 使用简单测试用例隔离问题（直接调用 vs 嵌套调用）
2. **代码阅读**: 仔细阅读 IL 生成代码，理解每一步的作用
3. **假设验证**: 通过修改代码验证假设（如尝试抛出异常来确认代码路径）
4. **逐步缩小范围**: 从大范围（所有测试）逐步缩小到具体的代码行

### 编译器开发要点
1. **类型一致性**: IL 栈操作必须严格遵守类型规则
2. **作用域隔离**: 局部变量需要隔离，全局符号需要共享
3. **测试驱动**: 每次修改后立即测试，避免累积问题
4. **文档重要性**: 详细的注释和文档能避免误用API
