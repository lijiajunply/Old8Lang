# OldLib 包与模块测试修复验证

- 时间：2026-10-22 21:56（Asia/Shanghai）
- 范围：`OldLib` 包入口 + 模块测试 10 个既有失败（含由此暴露的 8 个并发失败）
- 结论：**OldLib 可正常使用，模块测试 520/520 全部通过**；全量单测失败数仍为既有基线 737

## 1. OldLib 包

| 项目 | 变更 |
|------|------|
| `packages/OldLib/index.old8`（两个夹具） | 从空文件改为直接声明 `Old8LangLib` 的 `extern`：MathLib / Time / CryptoLib / FileLib / OS / Csv / Terminal |
| `Async.old8`、`CollectionLib.old8`、`Json.old8` | 删除——`AsyncLib` / `SortLib` / `CollectionLib` / `JsonLib` 在 C# 侧已不存在 |
| `tests/test_thirdparty.old8` | 新增 OldLib 段：`Sqrt` / `Factorial` / `Sha256Hash` / `GetLocalTime` / `ParseCsvLine` |

说明：`index.old8` 若用 `import "Time"` 这类相对导入，会先命中同名标准库（`Time`/`Crypto`/`File`…），
`MathLib` 则根本解析不到；直接写 `extern` 才能把符号真正导入调用方作用域。

| 失败项 | 根因 | 修复 |
|--------|------|------|
| `JsonLibTests`（4） | `Json` 标准库已在 `bc5fdb16` 移除，现为全局函数 `JsonSerialize` | 删除过期测试类 |
| `NetLibTests`（2） | 测试脚本仍 `import Json` + `Json.Serialize` | 改用全局 `JsonSerialize(postData)` |

| `UnifiedModuleArchitectureTests`（1） | 测试用 `Compile(ast, "test", ...)`，丢失源码路径导致相对导入解析到 `bin/`；且 IL 模式不注册模块别名 | 测试传真实路径；IL 模式实现别名支持 |
| `LazyImportSyntaxTest`（1） | 同上，且模块顶层变量未内联导致 `tm.value` 报未声明 | 同上 + 导入时内联模块体 |
| `DatabaseLibTests`（附带 8 个） | 编译器/解释器两组测试共用内存库名（`testdb_*`） | 解释器侧改用 `itestdb_*` 前缀 |

## 3. IL 模式模块别名实现

- `Compiler.Compile`：编译前把带别名的导入注册到解释器作用域（`ImportStatement.Run`），
  供 `ExecuteModule` 的编译期求值与运行时回退使用。
- `LocalManager.ModuleAliases`：记录本次编译的模块别名。
- `DotOperatorILHelper`：`tm.member` 展开为同名符号——有参数时走 `FunctionCallExpression`，
  无参数时按变量/常量加载。
- `BlockStatement.GenerateImportIl(includeBody: true)`：导入模块时把模块顶层语句一并内联，
  否则模块变量不会成为 IL 局部变量。
- 模块测试基类与 `UnifiedModuleArchitectureTests` 改为向 `Compiler.Compile` 传真实文件路径。
