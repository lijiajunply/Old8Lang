## 1. 本批改动

| 变化 | 说明 |
|------|------|
| `MatchCase`、`TuplePattern`、`TuplePatternElement`、`RangePattern` | 从 Runtime 的 `Expression/Advanced/Patterns` 迁入 `Old8Lang.Syntax/AST/Expressions`，命名空间 `Old8Lang.AST.Expression.Intermediates` 不变 |
| `SelectCase`、`ImportItem` | 从 `SelectStatement.cs`/`ImportStatement.cs` 中拆出为 Syntax 独立文件，命名空间不变 |
| `ClassFieldSetStatement` | 迁入 Syntax（内部辅助节点，仍不支持 Visitor 访问） |
| 匹配执行辅助 | `MatchCase` 的 `IsMatch`、元组/类型/范围匹配与运行时值判定移入 Runtime 的 `MatchCaseRuntimeExtensions`；仓库内 `matchCase.IsMatch(...)` 调用改为扩展方法，写法不变 |
| 生成代码 | Runtime 生成节点保持 69（本批不涉及 Visitor 节点）；遗留 partial 基线 21 → 20 |
| 测试 | 程序集归属断言补全；`MatchCase` 的模式匹配行为由既有 Interpreter/VM/Parser 用例覆盖 |

行为保持：模式匹配的通配符/变量绑定/值/元组/类型/范围语义、绑定字典与守卫条件作用域、导入项别名默认值、
Select 收发 case 的构造与块引用均未改动。

## 3. 未完成与下一步

1. 解析器仍在 Runtime，剩余主要构造点包括 `FuncLangValue`/`AsyncFuncLangValue`（函数与 lambda）、
   `FuncInit`/`ClassInit`/`EnumInit`、`FuncRunStatement`、`ForIn`/`AsyncForIn`、`NestedIndexAccess` 等。
2. `FuncInit`/`ClassInit` 依赖 `FuncLangValue`/`TypeTemplate`，需要先引入函数语法与运行时闭包的边界。
3. `ImportStatement` 本身仍依赖模块系统，需与最小共享契约一起拆分。
