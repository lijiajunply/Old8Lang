## 1. 结论速览

| 范围 | 数量 | 状态 | 验证方式 |
|------|-----:|------|----------|
| IL 模式显式抛 NotSupported 的方法 | 29 | ✅ 全部实现 | `-il` 实跑，输出与 `-f` 逐行一致 |
| VM 模式显式抛 NotSupported 的方法 | 14 | ⚠️ 10 完成 / 4 阻塞 | Array 6 + Task 4 ✅；Thread 4 见 §5 |
| 扩展方法 IL 支持 | 1 | ✅ 已可用 | `-il` 实跑 3 个既有扩展方法用例，数值与 `-f` 一致 |
| `ValueExpression.LoadIlValue` | 1 | ✅ 已实现 | 委托给被包装值自身的 IL 表示 |

附带修复的阻塞性缺陷（否则目标方法无法真正可用）：

1. IL 代码生成从不初始化实例方法注册表 → 只要程序没触发过解释器实例方法分派
   （例如只用 Thread 的原生 `Dot`），注册表就是空的，所有实例方法都解析不到。
2. IL 模式下 lambda / 函数引用无法作为「函数值」传递（`FuncLangValue.LoadIlValue` 原为空实现）。
3. IL 模式裸调用语句（`d.ForEach(f)`、`l.Count()`）不弹栈 → 无效 IL。
4. `IlValueBridge.Wrap(object?)` 对值类型实参缺少装箱（`SingleOrDefault(-1)`、`WithTimeout(1000)`）→ 无效 IL。
5. IL 下 `spawn(f)` 只发 `ldnull`（拿不到线程对象）；`Thread.Start/Join/IsAlive` 的 IL helper
   按原生 `System.Threading.Thread` 写，与栈上的 `ThreadLangValue` 不匹配。
6. 解释器 `ThreadRetryHelper` 重试时没有启动新线程 → `spawn(f).Retry(n)` 必抛
   `ThreadStateException: Thread has not been started`。
7. IL 下 `Task.FromException("消息")` 直接调用 .NET 的 `FromException<T>(Exception)` → 运行期参数异常。

**实现机制**（新增基础设施）：

- `Old8Lang/InstanceMethods/Core/IlValueBridge.cs`（新）
  - `Wrap(object?)`：原生值 → `LangValueType`（基础类型 / 字符串 / 数组→`ArrayLangValue` /
    集合→`ListLangValue` / 字典→`DictionaryLangValue` / 委托→函数值 / `Task`→`TaskLangValue`）；
  - `Unwrap(LangValueType)`：反向转换；
  - `EmitLoadWrapped(...)`：生成「加载表达式 → 值类型装箱 → `Wrap`」的 IL 序列
    （函数字面量走 `WrapFunction`，避免把委托按 lambda 返回类型错误装箱）；
  - `IlDelegateFuncLangValue`：把编译好的 .NET 委托包装成 `FuncLangValue`（形参列表按委托真实参数构造，
    因此 `SortBy` 这类按 `func.Ids.Count` 区分模式的实现能正确分支）。
- `Old8Lang/InstanceMethods/Core/IIlNativeValueInstanceMethod.cs`（新）：标记接口。
  IL 解析在常规映射失败后，会按「等价 LangValueType」（`List<T>→ListLangValue`、
  `T[]→ArrayLangValue`、`Dictionary<K,V>→DictionaryLangValue`、`Task→TaskLangValue`）再解析一次，
  但只采纳实现了该接口的方法，避免既有实现（假定接收者已是 `LangValueType`）生成无效 IL。
- `FuncLangValue.LoadIlValue` 现在会为 lambda 生成委托常量并加载；`LangId.LoadIlValue`
  支持把具名函数当函数值传递；lambda 会继承外层函数委托表（因此 lambda 内可以按名字调用其它函数）。
- `FuncLangValue.OutputType` 的 lambda 判定通过新增的 `IsLambdaExpression` 暴露，`BaseInstanceMethod`
  在重载解析时把 lambda/具名函数引用视为 `FuncLangValue`（解释器模式行为不变）。

**已知边界**（既有，不是本次引入）：

- IL 模式下「在方法调用结果上直接链式调用」仍不可用，例如 `l.FindAll(f).Count()`、
  `l.Count().ToStr()` 都会生成无效 IL（`Operation.OutputType(ILGenerator, LocalManager)` 对嵌套
  表达式的左值类型取的是非 IL 的 `OutputType(LocalManager)`，恒为 `object`）。测试文件因此先把结果
  赋给变量。已记入 `Todo.md`。
- IL 模式 lambda 仍不能读写外层普通局部变量；lambda 需要类型注解。

## 4. 虚拟机模式：Array 6 个排序 + Task 4 个方法

**Array**（`TestFiles/VirtualMachine/array_sort_vm_test.old8`）：

```bash
dotnet Old8Lang.App/bin/Debug/net10.0/Old8Lang.App.dll -vm TestFiles/VirtualMachine/array_sort_vm_test.old8
```

输出（全部断言通过）：

```
QuickSort OK / HeapSort OK / SelectionSort OK / InsertionSort OK / MergeSort OK / BubbleSort OK
6 种算法一致 OK / 原数组不被修改 OK / 混合 int/double OK / Sort/IsSorted OK / Sort(comparer) OK
All Array Sort VM Tests Passed
```

- VM 下数组是原生 `object?[]`，6 个算法均为真实独立实现（快排三数取中、堆排迭代下沉、归并稳定等），
  统一归一化接收者、返回 `object?[]`。
- 比较策略：`null` 最前 → 整数用 `decimal`、含浮点用 `double` → `bool` false<true → `char` 字符序 →
  **string 按长度再按序数**（对齐解释器 `StringLangValue.Less/Greater` 的按长度语义，消除跨模式分歧）。
- 附带修复：`LangListSortMethod` / `LangListIsSortedMethod` 的 VM 实现对 `object?[]` / `List<object?>`
  的兜底（此前只认 `ILangList`，导致 `arr.Sort()` / `arr.IsSorted()` 在 VM 下必失败）。

**Task**（`TestFiles/VirtualMachine/task_methods_vm_test.old8`）：

```bash
dotnet Old8Lang.App/bin/Debug/net10.0/Old8Lang.App.dll -vm TestFiles/VirtualMachine/task_methods_vm_test.old8
```

输出：

```
Then OK / ContinueWith OK / finally-ran / Finally OK / Catch OK / 链式 Then OK
```

- continuation 在线程池线程执行，而 `VMContext.CurrentVM` 是 `[ThreadStatic]`，

  避免被包成 `NativeAnyLangValue` 打印成 `NativeObject(42)`）。

## 4.5 IL 模式：扩展方法与 `ValueExpression.LoadIlValue`

**扩展方法**（既有用例，`TestFiles/InterpreterTests/`）：

| 用例 | 解释器 | IL（改动后） |
|------|--------|-------------|
| `test_extension_string.old8`（`extension string { func getValue() }`） | `hello` | `hello` |
| `test_extension_int_builtin.old8`（扩展体内用 `this * 2` 与全局 `Print`） | `1010` | `1010`（改动前 IL 直接 `NotImplementedException`；中间版本因用空 `VariateManager` 执行函数体而 NRE，已改为复用声明阶段的管理器） |
| `test_extension_shadowing_builtin.old8` | `42` | `42` |

实现：`ExtensionDeclaration` 的注册发生在编译前的解释器预执行阶段，
因此声明节点在 IL 下不再抛 `NotImplementedException`，只生成「无 IL」；
调用点由 `ExtensionMethodWrapper.GenerateIl` 生成代码——把包装器作为编译期常量
（新增 `Old8Lang/Compiler/RuntimeConstantRegistry.cs`）传入，接收者/参数经
`IlValueBridge.EmitLoadWrapped` 转成 Old8Lang 值，再交给运行期 helper
`InvokeExtension` 按解释器语义执行扩展方法体，结果 `Unwrap` 回原生表示。

**`ValueExpression.LoadIlValue`**（`Old8Lang/Runtime/ReflectionHelper.cs`）：
不再抛 `NotImplementedException`，改为委托给被包装值自身的 `LoadIlValue`/`OutputType`
（基础类型加载原生常量、集合构造原生集合），保证栈类型与 `OutputType` 一致。

## 5. 未完成 / 阻塞项

| 项 | 状态 | 原因与证据 |
|----|------|-----------|
| VM 模式 `Thread.Then` / `Cancel` / `Retry` / `WithTimeout` | ❌ 阻塞 | 这 4 个方法 `TargetType = ThreadLangValue`，而 VM 的线程对象是 `VMThreadLangValue`（整数线程 id + `Concurrency.ResourceManager`，见 `SpawnFunction.cs:183`）。VM 分发（`VirtualMachine.Helpers.ReflectionAndTasks.cs:60/65`）精确匹配与 `VMTypeMapper` 等价映射都得不到 `ThreadLangValue`，方法体一行都不会执行（实测报 `类 'VMThreadLangValue' 中未找到方法 'X'`）。即便改 `TargetType`，VM 线程模型也没有取消/超时/重试原语（`ResourceManager` 只有创建/启动/Join/IsAlive/Dispose）。属于改线程模型的独立工作，已记入 `Todo.md`。 |
| IL 模式方法结果直接链式调用 | ❌ 未修 | `l.FindAll(f).Count()`、`l.Count().ToStr()` 生成无效 IL，根因在 `Operation.OutputType(ILGenerator, LocalManager)` 对嵌套左值取非 IL 类型。既有缺陷（改动前 `l.Count().ToStr()` 同样失败），已记入 `Todo.md`。 |
| IL 模式 lambda 捕获外层局部变量 | ❌ 未修 | 既有边界（`BuildLambdaDynamicMethod` 的 `funcLocal` 不携带外层局部变量）；本次只额外让 lambda 继承外层**函数**委托表。 |
| 无类型注解的递归函数在 IL 下栈溢出 | ❌ 未修（既有） | `func factorial(n) { if n <= 1 { return 1 } return n * factorial(n - 1) }` 用 `-il` 运行 → `Stack overflow ... at DynamicClass.factorial(System.Object)`。**在基线 worktree（HEAD 67005c8c）用同一文件同样复现**，非本次引入；它会让 `dotnet test` 整轮中止，故失败集合的比对在崩溃点截断。建议 IL 模式拒绝无注解参数（IL 本要求完整类型注解）。已记入 `Todo.md`。 |
| `Reports/2026-10-09-22-56` 的 P0（IL 校验大面积失败） | ❌ 未修 | 本次只做第 5 节清单，P0 仍是仓库最高优先项。 |

## 7. 后续建议（按优先级）

1. 修 `Operation.OutputType(ILGenerator, LocalManager)` 的嵌套左值类型问题 → 解开 IL 链式调用，
   预计能连带减少大批 IL 用例失败（P0 方向）。
2. VM 线程模型补齐：给 `VMThreadLangValue` 增加 `Then` / `WithTimeout` / `Retry` / `Cancel`
   （需要 `ResourceManager` 支持取消令牌与保存原始函数），或明确文档化为不支持。
3. IL 模式闭包捕获外层局部变量（`funcLocal` 携带外层局部变量快照 / 提升为字段）。
4. 把 `List`/`Dictionary`/`Array` 其余的 IL 实现（`Map` / `Filter` / `Reduce` / `Sort` 等，
   目前是 `Ldnull` 桩或按旧约定写死）迁移到 `IIlNativeValueInstanceMethod` + `IlValueBridge` 体系。
