跨文件策略（为避免误报）：

- 只对**顶层符号**（函数、类、全局变量）跨文件；方法、参数、属性仍是文件内作用域。
- 若另一个文件自己声明了同名顶层符号，该文件整体跳过——把每个脚本视为独立程序，
  避免 `TestFiles/` 下大量同名 `func main` 互相污染引用计数。
- 引用是 token 级的：排除成员访问（`obj.name` 的 `name`）与参数声明（`(a: int)` 的 `a`）。

## 3. 关键发现

1. **依赖限制记录有误**：0.19.9 的程序集中存在
   `InlayHint` / `InlayHintsHandlerBase` / `IInlayHintsHandler`，
   以及 `CallHierarchy*`、`TypeHierarchy*` 的 Handler 基类。已在 TODO 中更正。
   本次用该 API 实现了参数名内联提示，说明“必须升级 OmniSharp 才能做 Inlay Hint”不成立。
2. **扩展默认服务器路径原本不可用**：旧代码只尝试 `server/Old8Lang.LanguageServer`，
   而仓库里只有 `.dll`/`apphost`。新逻辑支持 `.dll` 与源码项目回退，扩展才能在开发环境直接启动。
3. **Code Lens 的命令需要客户端转发**：使用自定义 `old8lang.showReferences`，
   由扩展转成 VS Code 内置 `editor.action.showReferences`，避免依赖未注册的内置命令参数格式。
4. **跨文件索引必须保守**：`TestFiles/` 中大量脚本各自声明同名函数，
   若不做同名顶层符号隔离，引用计数会被其他独立脚本污染。

## 4. 未完成项与原因

| 项 | 状态 | 原因 |
|----|------|------|
| Debug Adapter（DAP） | 未实现 | 运行时没有 DAP 服务器；VM 的 `--debug-session` 是交互式终端调试器，LSP 调试是自定义请求，均无法直接对接 VS Code DAP。建议先新增 `--dap` 模式 |
| Inline Values | 未实现 | 需要暂停中的调试变量快照；`DebugProfilerService` 只有会话与事件队列，没有可引用的变量值 |
| Call Hierarchy / Type Hierarchy | 未实现 | 协议 API 已可用，但需要调用关系/继承关系的建模与 UI 验证；`SymbolInfo.Calls` / `CalledBy` 可作起点 |
| 作用域链 | 未完成 | 局部变量遮蔽、块级作用域尚未进入符号表模型 |
| 成员访问类型推断 | 未完成 | 继承成员、静态成员、链式调用仍未完整建模 |
| 诊断增强 | 未完成 | 类型不匹配、未使用变量、成员不存在等仍需类型检查器支持 |
| 防抖诊断 / 大文件基线 | 未完成 | 当前诊断仍在 `DocumentManager` 解析后同步推送 |
| 替换 token-based workaround | 未完成 | 仍依赖 token 位置弥补 AST 位置缺失 |
