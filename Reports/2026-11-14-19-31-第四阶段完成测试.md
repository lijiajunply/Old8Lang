## 最终结构

```text
Old8Lang.App / LanguageServer / Benchmarks / Tests
                      ↓
        Old8Lang.Hosting（显式注册三个后端与官方模块）
        ↙              ↓               ↘
Interpreter        Compiler        VirtualMachine
（Visitor/宿主/调试器）（Visitor/IL/异步）（Visitor/VM/字节码）
        ↘              ↓               ↙
                 Old8Lang.Runtime
   运行时值、内置函数、模块/类型系统、字节码格式、
   最小契约（RuntimeVisitors/ILangInterpreter/IVirtualMachine/
   IBytecodeCompiler/IAsyncStateMachineGenerator/IlCompilerOptions）、
   共享执行状态（VariateManager/ScopeLayer/LocalManager/类型推断）
                      ↓
   Old8Lang.Syntax（语法节点与解析器，只引用 Core）
                      ↓
                 Old8Lang.Core
```

三个后端互不引用，Runtime 不引用任何后端。宿主为每个实例持有独立的
`StandardLibraryCatalog`；进程默认目录只作为 CLI/LSP 与无参构造器的兼容边界。

## 最终验证

构建：`/usr/local/share/dotnet/dotnet build Old8Lang.sln` **0 错误**。

| 测试组 | 结果 |
|---|---|
| Architecture | 73 通过 |
| Parser | 889 通过 |
| Interpreter（排除 NetLibTests） | 1959 通过 / 1 跳过 |
| VirtualMachine | 1083 通过 |
| LanguageServer | 474 通过 / 2 跳过 |
| InstanceMethods / TypeSystem / Libraries / Diagnostics | 33 / 65 / 95 / 47 通过 |
| Compiler 各分组 | 与基线 `34ddd4dd` 逐组失败/跳过数量一致（既有 IL 问题） |

默认档全量单进程运行仍会在 `Compiler.Classes` 的既有 IL 用例处使测试主机崩溃；该现象在基线
`34ddd4dd` 上同样复现，按命名空间分组运行的结果已完整记录在阶段 4.2 报告中。此项不阻塞
阶段 4 验收，仍是 `Todo.md` 记录的既有 IL 缺陷。
