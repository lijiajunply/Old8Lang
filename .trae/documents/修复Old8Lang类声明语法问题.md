# 修复Old8Lang类声明语法问题

## 问题分析

通过对代码库的分析，我发现了以下类声明语法相关的问题：

1. **静态成员未处理**：`GenerateIl`方法中未调用`DefineStaticMembers`，导致编译模式下静态成员无法生成
2. **访问修饰符处理不完整**：
   - 方法访问修饰符硬编码为public，未使用成员实际的修饰符
   - 字段修饰符处理逻辑存在问题
3. **构造函数生成有限**：仅支持无参数构造函数，未根据类中定义的init方法生成对应构造函数
4. **缺少抽象类和抽象方法支持**：EBNF语法和实现中均未支持
5. **缺少属性、密封类、readonly字段等高级特性支持**

## 修复计划

### 1. 修复静态成员处理
- 在`GenerateIl`方法中添加对`DefineStaticMembers`的调用
- 确保静态字段和静态方法在编译模式下正确生成

### 2. 完善访问修饰符处理
- 修改`DefineMethodInternal`方法，根据`ClassMemberId`的修饰符设置方法访问级别
- 优化字段修饰符处理逻辑，确保protected等修饰符正确应用

### 3. 增强构造函数生成
- 分析类中的init方法，生成对应的构造函数
- 支持多参数构造函数，根据init方法的参数列表生成

### 4. 添加抽象类和抽象方法支持
- 在EBNF语法中添加抽象类和抽象方法的定义
- 修改`ClassInit`类，支持生成抽象类和抽象方法的IL代码

### 5. 优化现有实现
- 确保成员变量按声明顺序初始化
- 完善接口实现检查

## 实现步骤

1. 首先修复静态成员处理问题，确保编译模式下静态成员正常工作
2. 完善访问修饰符处理，确保不同访问级别正确应用
3. 增强构造函数生成逻辑，支持根据init方法生成构造函数
4. 逐步添加其他高级特性支持

## 测试计划

1. 编写测试用例验证静态成员在编译模式下的行为
2. 测试不同访问修饰符的类成员
3. 测试带有init方法的类构造
4. 测试抽象类和抽象方法（如果实现）

## 预期结果

- 编译模式下静态成员正常工作
- 类成员访问修饰符正确应用
- 支持根据init方法生成对应的构造函数
- 代码结构更清晰，扩展性更好
