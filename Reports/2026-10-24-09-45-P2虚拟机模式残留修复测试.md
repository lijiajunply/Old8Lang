## 2. 逐项改动

### 2.1 五个 VM `.old8` 用例

先在同一批文件上跑 `-f`，确认它们**并非虚拟机独有**：

| 文件 | 原失败原因 | 处理 |
|------|-----------|------|
| `DestructuringAssignmentTest.old8` | 元组模式 `(a, b) <- ...` 全模式未实现；且 `PrintLine(...)` 后以 `[` 开头的语句会被解析成索引 | 改写为语言支持的 `[a, b] <- 序列`，并在 `PrintLine` 行尾加分号 |
| `vm_gap_6_error_position.old8` | 运行期错误用例，末行缺 `error` 标记 | 末行改为注释 `// error`（不破坏运行期错误路径） |
| `legacy/vm_operator_overload.old8` | `init(v)` 必填却调用 `Number()` | 改为 `Number(10)` / `Number(20)` |
| `legacy/control_flow.old8` | 旧 `for j <- 0; ...; j <- j + 1` 语法 | 改为 `for j <- 0, j < 5, j++` |
| `legacy/vm_decorator.old8` | 旧 `-> func` 返回类型写法 | 去掉返回类型注解 |

改写 `DestructuringAssignmentTest` 时发现**真实 VM 缺口**：解释器支持 `[a, b] <- 序列`，
字节码只实现了元组模式（且解释器反过来不支持元组模式）。已在
`BytecodeVisitor.VisitSetStatement` 补齐数组解构：右值求值一次后存临时槽，按下标逐个写入
（局部变量 / 捕获变量 / 全局变量都覆盖），多余元素忽略。

### 2.2 静态类 TestRunner / Mock / TaskScheduler

- `VmStaticClassRegistry` 新增三个类的方法表，并新增「属性式成员」概念
  （`Task.Factory`、`Thread.CurrentThread`、`TaskScheduler.Default`）。
- `TestRunner.Describe` / `It` / `Test` / `RunTest` 由虚拟机自己执行传入的
  `ClosureValue` / `FunctionMetadata`（新增 `InvokeTestRunnerCallback`）；
  其余统计类方法（`RunAll` / `Clear` / `GetStatistics` …）通过新增的
  `TestRunnerClassLangValue.VmReusableMethods` 复用解释器实现。
- `Mock` 的 12 个静态方法全部只操作 `MockObjectLangValue`，直接复用
  （`MockLibClassLangValue.VmReusableMethods`）。
- `TaskScheduler.Default` 返回 `TaskSchedulerLangValue`，可作为
  `Task.Factory.StartNew` 的第二个参数。
- **顺带修好一个两种模式共有的缺陷**：`ConvertTestResult` / `GetStatistics` 构造
  `DictionaryLangValue` 后没有调用 `Run`，`Value` 为空，导致 `RunAll` 的返回值里
  测试名全空、全部判失败。现在构造后立即展开。

### 2.3 Task / Thread 静态类

- 删除 `Task.Delay` 第二参数的显式拒绝（`CancellationTokenLangValue` 本来就能通过
  `cts.Token` 得到）。
- 新增 `Task.Factory`（属性）与 `Task.Factory.StartNew`（1–2 参数，忽略调度器但校验类型）。
- `Thread.CurrentThread` 两种写法（属性 / 无参调用）都返回 `ThreadLangValue`。
- **静态类方法可作为函数值**：新增 `VmStaticMethodValue`，编译期把 `f <- Task.Delay`
  改写成带前缀的原生调用，运行期产出一个可调用值；`CallDynamic` / `InvokeCallable`
  再按限定名分发。
- 修 `ThreadLangValue` 的两个问题：`GetValue()` 返回 `this` 而基类 `ToString()`
  走 `GetValue()?.ToString()`，任何 `ThreadLangValue.ToString()` 都会无限递归（栈溢出）；
  同时补 `Id` 属性，使 VM 的反射式字段读取可用。

仍不支持（保持 `VM_UNSUPPORTED_ERROR`）：裸引用静态类名（`value <- Task`）、
静态类方法的命名参数。

### 2.4 错误信息中的 .NET 类型名

- `VMReflectionHelper` 新增 `DescribeTypeName(Type)`；虚拟机内新增
  `DescribeValueType` / `DescribeTypeName` 两个私有包装。
- 替换了属性访问、方法未找到、算术/比较、索引/切片/长度、类型转换、`TypeOf`、
  函数对象非法、求值栈诊断等 30 余处 `GetType().Name`。
- `GetValueTypeName` 的兜底改为 `DescribeValueType`，并新增 `LangValueType =>
  TypeToString()`，避免出现 `IntLangValue` / `Tuple`2`。

效果：

```text
类型 'List`1' 没有属性 'Foo'      →  类型 'List' 没有属性 'Foo'
类型 'Tuple' 没有属性 'Foo'       →  类型 'Tuple' 没有属性 'Foo'
无法对类型 List`1 和 Dictionary`2 →  无法对类型 List 和 Dictionary
```

### 2.5 异步函数显式 `return null`

`ConvertResultToLangValue` 原先把裸 `null` 一律当成「没有值」。实际上无返回值时
`CallFunction` 收尾已补 `VoidLangValue`，所以这里拿到裸 `null` 只可能来自显式 `null`。
改为统一走 `ToStaticClassArgument`（`null → NullLangValue`）：

```text
async func f() -> any { return null }
t <- f(); await t; PrintLine(t.ToString())
```

VM 与解释器现在都输出 `Task(Completed: Null)`；无返回值的函数仍是 `Task(Completed: )`。

### 2.6 异步函数装饰器（受阻，未实现）

现状仍是 `VM_UNSUPPORTED_ERROR`。补查发现根因不在虚拟机：

```old8
func wrap(f) {
    return async (x) -> { r <- await f(x); return r + 1 }
}
```

- 解释器：`NullReferenceException`（`Instance.Run`）
- 虚拟机：`AsyncFuncLangValue 暂不支持 Visitor 模式访问`

即三种模式都没有「异步 Lambda / 异步函数值」。装饰器的结果必须是异步函数值，
在这层能力落地前无法实现；已在 `Todo.md` §D 记录前置依赖，并把
`MODE_SUPPORT.md` 的说明改成准确原因。

### 2.7 调试 / 性能 / 反汇编工具接入

- `VirtualMachine.Tooling.cs`：新增 `Profiler` / `Debugger` 属性、`DebugPaused` 事件、
  `AddBreakpointsAtLine`、`GetFrameVariables`。仅当工具非 null 时在取指后调用探针，
  正常执行只多一次 bool 判断。
- `CallFrame` 增加内部 `ProfileStopwatch`；帧退出用嵌套 `try/finally` 保证调试器调用栈
  与计时器一定回收。
- `VMDebugger` 增加按函数限定的断点（`AddFunctionBreakpoint` / `HasBreakpoint(func, off)`），
  避免不同函数同名指令下标误命中；同一源码行只在「刚进入该行」时设一个断点。
- CLI `-vm` 新增：`--disasm`、`--profile`、`--debug-session`、`--break <行号>`；
  交互命令 `c/s/n/o/bt/p/h/q`。
