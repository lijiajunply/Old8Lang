# 阶段 3.2 IL 后端拆分测试报告

日期：2026-11-14 16:48  
范围：[plan.md](../Docs/architecture-migration/plan.md) 阶段 3「拆分执行后端」的 IL 后端子阶段。

## 目标

把 IL 生成引擎（`CompilerVisitor`）从 `Old8Lang.Runtime` 拆到独立程序集，使 Runtime 不再在
编译期构造 IL 访问器，并保持 IL 模式行为与既有基线一致。

## 改动

1. 新增 `Old8Lang.Compiler` 程序集，只引用 `Old8Lang.Runtime`。迁入：
   - `CompilerVisitor` 及 `CompilerVisitor.{Expressions,ExpressionsAndValues,SetValueToIl,Statements,Statements2,Values}.cs`；
   - `ScalarLiteralVisitors.cs`、`CallExpressionVisitors.cs`、`LambdaExpressionVisitors.cs`
     中的 IL 片段（字节码/类型推断片段暂留 Runtime，供阶段 3.3 迁出）；
   - `CompilerBackend` 注册入口与模块初始化兜底注册。
2. Runtime 的 `RuntimeVisitors` 增加 IL 契约：
   - `RegisterCompiler(Func<ILGenerator, LocalManager, IRuntimeVisitor<object?>>)`；
   - `CreateCompiler(ILGenerator, LocalManager)`，未注册时抛出带组合根指引的异常。
3. 替换 Runtime 内 449 处 `new CompilerVisitor(...)`（181 个文件）为契约调用。
4. 组合根 `Old8HostBuilder` 构造时同时注册解释与 IL 后端；App、LSP、Benchmarks、Tests
   显式引用 `Old8Lang.Compiler`。
5. `BackendAssemblyBoundaryTests` 扩展三条门禁：IL 程序集只引用 Runtime、不引用其他后端；
   IL 后端可通过契约注册并创建；Runtime 源码不得再直接 `new CompilerVisitor`。
6. Runtime 对 `Old8Lang.Compiler` 开放 `InternalsVisibleTo`，暂复用内部执行辅助。

## 验证

构建（`/usr/local/share/dotnet/dotnet build Old8Lang.sln`）：0 错误。

| 测试组 | 结果 |
| --- | --- |
| `Old8Lang.Tests.Architecture` | 52 通过，0 失败 |
| `Old8Lang.Tests.Interpreter` | 1967 通过，1 跳过，0 失败 |
| `Old8Lang.Tests.VirtualMachine` | 1082 通过，0 失败 |
| `Old8Lang.Tests.Compiler.Expressions` | 179 通过，41 失败；与 HEAD 基线逐项一致 |

说明：Compiler 全域测试主机仍在 IL 异常后中止，`Compiler.Expressions` 的 41 项失败在未改动
HEAD 上完全复现，属于 `Todo.md` 已记录的 IL 既有问题；本子阶段未改变 IL 生成逻辑。
测试使用 `/usr/local/share/dotnet/dotnet`（.NET 10 运行时）。

## 遗留

- `Compiler/`（`Compiler.Compile` 驱动、`LocalManager`、`RuntimeGlobals`、异步状态机、
  特化与验证辅助）仍在 Runtime：`LocalManager` 是 `IInstanceMethod` 与类型推断的共享编译契约，
  多个运行时值仍保留 IL 辅助方法。要把整个引擎迁出，需要先抽象这些共享契约，留待后续子阶段。
- 字节码/VM 后端尚未拆出，阶段 3 不标记完成。
