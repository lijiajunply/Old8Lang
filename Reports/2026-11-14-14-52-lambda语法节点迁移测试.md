日期：2026-11-14 14:52

状态：本批完成；阶段 2 整体未完成（函数声明、类声明、Import/Native、Linq、解析器、其余运行时值仍待拆分）。

## 1. 本批改动

| 变化 | 说明 |
|------|------|
| `LambdaExpression`（Syntax） | 新语法节点：返回类型注解（历史 `LangId` 表示）、参数、函数体、`IsAsync`、位置；`Accept` 走 `IVisitor` |
| 解析器 | `PrimaryParser.LambdaAndTuple`、`PrimaryParser.Main` 不再直接构造 `FuncLangValue`/`AsyncFuncLangValue`，统一产出 `LambdaExpression` |
| Runtime 适配 | 新增 `LambdaExpressionRuntimeFactory`：按 `IsAsync` 创建等价的 `FuncLangValue`（`isLambda: true`）或 `AsyncFuncLangValue`；闭包捕获仍由原 Visitor 负责 |
| 四个 Visitor | 新增 `VisitLambdaExpression`，委托给工厂后的原 `VisitFuncLangValue`/`VisitAsyncFuncLangValue` |
| VM | `ClosureCaptureAnalyzer` 识别 `LambdaExpression`，与 `FuncLangValue` 共用嵌套闭包分析 |
| IL | `GlobalVariableAnalysis` 收集 lambda 内引用的顶层变量；`IlValueBridge`/`ExtensionMethodWrapper`/`BaseInstanceMethod` 把 lambda 参数按函数值处理；`CompilerVisitor.SetValueToIl` 走原 lambda 闭包赋值路径 |

本批修复了迁移过程中由测试暴露的 3 处联动缺口（均为「只认 `FuncLangValue` 节点」的 AST 扫描/包装逻辑）：
VM 闭包捕获、IL 顶层变量提升、IL 自定义比较器参数包装。

## 3. 未完成与下一步

1. 具名函数声明仍由 `FunctionParser` 直接构造 `FuncLangValue` 并包进 `FuncInit`；下一步用同样思路引入函数声明语法。

3. `ImportStatement` 的模块加载逻辑仍在 Runtime；解析器整体迁移仍待函数/类声明完成后推进。
