# Data Model: 文档结构模型

**Date**: 2026-02-14
**Feature**: 001-update-docs-modes

## 概述

本文档定义文档更新项目的"数据模型"，即文档的结构化组织方式。虽然这不是传统意义上的数据模型（如数据库表结构），但它定义了文档实体、关系和属性，确保文档更新的一致性和完整性。

---

## 1. 文档实体

### 1.1 执行模式文档 (Execution Mode Documentation)

**定义**: 描述三种执行模式（解释模式、编译模式、VM模式）的文档内容

**属性**:
- 模式名称 (string): "解释模式" | "编译模式" | "VM模式"
- 英文名称 (string): "Interpretation Mode" | "Compilation Mode" | "Bytecode VM Mode"
- 实现位置 (path): 核心类和 Visitor 的文件路径
- 工作机制 (text): 执行流程的文字描述
- 特点列表 (list): 功能特性和限制
- 完成度 (percentage): 实现完成度百分比
- 适用场景 (list): 推荐使用场景
- 命令行参数 (string): CLI 参数和示例

**出现位置**:
- CLAUDE.md (概述)
- Docs/ARCHITECTURE.md (详细说明)
- Docs/CLI_GUIDE.md (命令参数)
- Docs/MODE_COMPLETION_STATUS.md (完成度统计)

---

### 1.2 架构组件文档 (Architecture Component Documentation)

**定义**: 描述核心架构组件（Visitor、AST、Parser、TypeSystem）的文档内容

**属性**:
- 组件名称 (string): "Visitor Pattern" | "AST" | "Parser" | "TypeSystem"
- 实现位置 (path): 组件的文件路径
- 职责说明 (text): 组件的主要职责
- 接口定义 (code): 关键接口或基类
- 实现列表 (list): 具体实现类
- 交互关系 (diagram): 与其他组件的交互
- 扩展方式 (text): 如何扩展组件

**出现位置**:
- CLAUDE.md (高层概述)
- Docs/ARCHITECTURE.md (详细说明)
- Docs/ADVANCED_TOPICS.md (高级主题)

---

### 1.3 API 参考文档 (API Reference Documentation)

**定义**: 描述标准库模块和方法的文档内容

**属性**:
- 模块名称 (string): "Old8LangLib" | "Old8Lang.NetLib" | etc.
- 功能类别 (string): "Math" | "File" | "Network" | etc.
- 方法签名 (code): 函数签名和参数类型
- 参数说明 (table): 参数名称、类型、说明
- 返回值 (text): 返回值类型和说明
- 示例代码 (code): 可运行的示例
- 模式支持 (list): 哪些执行模式支持该 API

**出现位置**:
- Docs/API_REFERENCE.md (完整参考)
- Docs/API_Mode_Comparison.md (模式对比)

---

### 1.4 命令行参考文档 (CLI Reference Documentation)

**定义**: 描述 CLI 命令和参数的文档内容

**属性**:
- 命令名称 (string): 命令或参数名称
- 参数格式 (string): 参数语法
- 功能说明 (text): 命令的功能描述
- 使用示例 (code): 完整的命令行示例
- 相关模式 (string): 关联的执行模式
- 实现文件 (path): 命令实现的文件路径

**出现位置**:
- CLAUDE.md (常用命令)
- Docs/CLI_GUIDE.md (完整参考)

## 2. 文档关系

### 2.1 层次关系

```
CLAUDE.md (入口文档)
    ├─→ Docs/ARCHITECTURE.md (架构详细说明)
    ├─→ Docs/CLI_GUIDE.md (命令行参考)
    ├─→ Docs/API_REFERENCE.md (API 参考)
    ├─→ Docs/LANGUAGE_FEATURES.md (语言特性)
    └─→ Docs/PERFORMANCE_GUIDE.md (性能指南)
```

**说明**:
- CLAUDE.md 作为入口文档，提供高层概述和快速导航
- 详细文档在 Docs/ 目录下，按主题组织
- 文档间通过相对路径链接

---

### 2.2 引用关系

**执行模式文档引用**:
- CLAUDE.md → 简要说明 → 链接到 ARCHITECTURE.md
- ARCHITECTURE.md → 详细说明 → 引用代码位置
- CLI_GUIDE.md → 命令参数 → 引用执行模式

**架构组件文档引用**:
- CLAUDE.md → 高层架构 → 链接到 ARCHITECTURE.md
- ARCHITECTURE.md → 详细架构 → 引用代码文件
- ADVANCED_TOPICS.md → 高级主题 → 引用架构组件

**API 文档引用**:
- CLAUDE.md → 标准库概述 → 链接到 API_REFERENCE.md
- API_REFERENCE.md → 完整 API → 引用模块文件
- API_Mode_Comparison.md → 模式对比 → 引用 API 文档

---

### 2.3 交叉引用

**模式 ↔ 架构**:
- 执行模式文档引用 Visitor 实现
- 架构文档说明每种模式的实现机制

**模式 ↔ API**:
- 执行模式文档说明功能支持差异
- API 文档标注模式兼容性

**命令 ↔ 模式**:
- CLI 文档列出每种模式的命令参数
- 执行模式文档引用相关命令

## 3. 文档属性

### 3.1 元数据属性

每个文档文件包含以下元数据：

- **标题** (H1): 文档的主标题
- **创建日期**: 文档创建时间
- **最后更新**: 最后修改时间
- **版本**: 文档版本号（如适用）
- **作者**: 文档作者或维护者

---

### 3.2 内容属性

#### 标题层级

- **H1** (`#`): 文档标题（每个文档一个）
- **H2** (`##`): 主要章节
- **H3** (`###`): 子章节
- **H4** (`####`): 详细说明
- **H5** (`#####`): 更细粒度的说明（少用）

#### 代码块

**属性**:
- 语言标注: `old8lang`, `csharp`, `bash`, `text`
- 语法高亮: 根据语言自动应用
- 注释: 包含关键步骤的注释
- 输出: 提供预期输出（如适用）

**示例**:
````markdown
```old8lang
// 这是一个示例
function greet(name: string) {
    print("Hello, " + name)
}

greet("World")
// 输出: Hello, World
```
````

#### 表格

**属性**:
- 表头: 使用粗体
- 对齐: 左对齐或居中
- 列数: 2-6 列（保持可读性）
- 行数: 根据内容，避免过长

**示例**:
```markdown
| 特性 | 解释模式 | 编译模式 | VM 模式 |
|------|---------|---------|---------|
| 启动速度 | 快 | 慢 | 中等 |
| 运行性能 | 中等 | 高 | 中等偏高 |
```

#### 链接

**内部链接**:
- 格式: `[文本](./relative/path.md)`
- 示例: `[架构文档](./Docs/ARCHITECTURE.md)`

**外部链接**:
- 格式: `[文本](https://example.com)`
- 示例: `[.NET 文档](https://docs.microsoft.com/dotnet)`

**代码位置引用**:
- 格式: `path/to/file.cs:line_number`
- 示例: `Old8Lang/Interpreter/LangInterpreter.cs:42`

#### 列表

**无序列表**:
- 使用 `-` 或 `*`
- 嵌套使用缩进

**有序列表**:
- 使用 `1.`, `2.`, etc.
- 自动编号

**任务列表**:
- 使用 `- [ ]` (未完成) 或 `- [x]` (已完成)

---

### 3.3 格式属性

#### 强调

- **粗体**: `**文本**` - 用于重要术语
- *斜体*: `*文本*` - 用于强调（少用）
- `代码`: `` `文本` `` - 用于代码片段、文件名、命令

#### 引用

```markdown
> 这是一个引用块
> 用于重要说明或警告
```

#### 分隔线

```markdown
---
```

用于分隔主要章节

## 5. 文档验证规则

### 5.1 准确性验证

- ✅ 所有技术信息与代码实现一致
- ✅ 文件路径和行号准确
- ✅ 代码示例可运行
- ✅ 版本号和完成度准确

### 5.2 完整性验证

- ✅ 所有三种执行模式都有说明
- ✅ 所有标准库模块都有文档
- ✅ 所有 CLI 命令都有参考
- ✅ 所有架构组件都有说明

### 5.3 一致性验证

- ✅ 术语使用一致（中英文对照）
- ✅ 格式风格统一
- ✅ 链接有效
- ✅ 代码块语言标注正确

### 5.4 可读性验证

- ✅ 标题层级清晰
- ✅ 段落长度适中
- ✅ 表格易于阅读
- ✅ 代码示例有注释

## 6. 文档更新工作流

### 6.1 信息收集

1. 从代码中提取准确信息
2. 验证信息的正确性
3. 组织信息结构

### 6.2 内容编写

1. 按照模板编写内容
2. 添加代码示例
3. 创建对比表格
4. 建立交叉引用

### 6.3 质量检查

1. 运行代码示例验证
2. 检查链接有效性
3. 审查格式一致性
4. 验证信息准确性

### 6.4 发布

1. 提交文档更新
2. 更新变更日志
3. 通知相关人员

## 7. 总结

本数据模型定义了文档更新项目的结构化组织方式，包括：

- **4 类文档实体**: 执行模式、架构组件、API 参考、命令行参考
- **3 种文档关系**: 层次关系、引用关系、交叉引用
- **多种文档属性**: 元数据、内容、格式
- **4 个文档模板**: 执行模式对比、架构组件、API 文档、命令行参考
- **4 类验证规则**: 准确性、完整性、一致性、可读性

遵循本数据模型可确保文档更新的质量和一致性。
