# 阶段 3.3 字节码/VM 后端拆分测试报告

日期：2026-11-14 16:54  
范围：[plan.md](../Docs/architecture-migration/plan.md) 阶段 3「拆分执行后端」的字节码/VM 后端子阶段。

## 目标

把字节码生成引擎（`BytecodeVisitor`）从 `Old8Lang.Runtime` 拆到独立程序集，使 Runtime
不再在编译期构造字节码访问器，并保持 VM 模式行为与既有基线一致。

## 改动

1. 新增 `Old8Lang.VirtualMachine` 程序集，只引用 `Old8Lang.Runtime`。迁入：
   - `BytecodeVisitor` 及其 20 个分文件；
   - `ScalarLiteralVisitors.cs`、`CallExpressionVisitors.cs`、`LambdaExpressionVisitors.cs`
     中的字节码片段（类型推断片段留在 Runtime）；
   - `VirtualMachineBackend` 注册入口（组合根显式调用）。
2. Runtime 新增 `IBytecodeVisitor` 契约（`IRuntimeVisitor<Instruction?>` +
   `GetInstructions()` + `MaxStackSize`），`BytecodeCompiler` 的 6 处
   `new BytecodeVisitor(this)` 改为 `RuntimeVisitors.CreateBytecode(this)`。
3. `RuntimeVisitors` 增加 `RegisterBytecode` / `CreateBytecode` / `HasBytecode`。
4. 组合根 `Old8HostBuilder` 同时注册解释、IL 与字节码/VM 后端；App、LSP、Benchmarks、Tests
   显式引用 `Old8Lang.VirtualMachine`。
   注册类位于 `Old8Lang.BytecodeBackend` 命名空间，避免与 `Old8Lang.Bytecode.VM.VirtualMachine`
   类型产生命名空间/类型解析冲突。
5. `BackendAssemblyBoundaryTests` 增加三条门禁：VM 程序集只引用 Runtime、不引用其他后端；
   VM 后端可通过契约注册并创建；Runtime 源码不得再直接 `new BytecodeVisitor`。
6. Runtime 对 `Old8Lang.VirtualMachine` 开放 `InternalsVisibleTo`。

说明：

- `NetLibTests` 的 8 个用例并发访问 `jsonplaceholder.typicode.com`，连续全量运行时会因外部
  限流/连接抖动出现 1~7 项失败；单独重跑可恢复。该现象未在本轮引入，已记录到 `Todo.md`
  的测试完成性条目；排除该组后解释器回归为 0 失败。
- Compiler 既有失败与前面子阶段一致（见 `Todo.md`），本子阶段未修改 IL 生成逻辑。
- 测试使用 `/usr/local/share/dotnet/dotnet`（.NET 10 运行时）。

## 遗留

- `Bytecode/`（`BytecodeCompiler`、`VirtualMachine`、指令集、模块加载、序列化）仍在 Runtime：
  `BytecodeCompiler` 是 VM 的执行/编译状态，Runtime 的多个值类型与反射辅助仍引用
  `Bytecode.Core`/`Metadata`/`VMContext`。把整个字节码引擎迁出需要先抽象这些共享契约，
  留待后续子阶段。
- `Compiler/` 引擎同样仍在 Runtime。三个后端访问器已独立，阶段 3 的「程序集分别构建、
  无循环依赖」门禁已覆盖，但完整引擎拆分与公开 API 迁移说明尚未完成，阶段 3 不标记完成。
