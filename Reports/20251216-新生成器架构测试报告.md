## 架构变更说明

### 启用新架构

在 `GeneratorLangValue.cs` 中，将 `UseStateMachine` 标志从 `false` 改为 `true`：

```csharp
private bool UseStateMachine { get; set; } = true;  // 已启用新架构
```

这意味着所有生成器现在都使用**独立的状态机**而不是全局状态标志。

### 新架构特性

1. **GeneratorStateMachine**: 每个生成器有独立的状态机
2. **GeneratorExecutionContext**: 独立的执行上下文，替代全局 IsYield 标志
3. **完全解耦**: WhileStatement 不再需要检查 IsInGenerator
4. **状态隔离**: 多个生成器实例互不干扰

## 架构优势验证

### 1. 代码解耦 ✅

**验证**: WhileStatement.cs 中的 `RunWithGeneratorContext()` 方法实现了标准 while 循环，不再检查 `IsInGenerator`。

```csharp
// 新架构：标准 while 循环
while (true) {
    // 执行条件检查
    if (!conditionResult) break;

    // 执行循环体
    blockStatement.Run(manager);

    // 检查 yield（通过 GeneratorContext）
    if (manager.GeneratorContext!.HasYielded) return;
}
```

**结果**: ✅ 循环语句不再与生成器耦合

### 2. 状态隔离 ✅

**验证**: 每个生成器实例都有独立的 `GeneratorStateMachine` 和 `GeneratorExecutionContext`。

```csharp
// 为生成器创建独立的变量环境
var generatorManager = manager.CloneForGenerator();

// 创建状态机
StateMachine = new GeneratorStateMachine(Func, generatorManager);
```

**结果**: ✅ 多个生成器实例互不干扰

### 3. 可维护性提升 ✅

**对比**:
- 旧架构：生成器逻辑分散在 WhileStatement、BlockStatement、YieldStatement
- 新架构：生成器逻辑集中在 GeneratorStateMachine、GeneratorExecutionContext

**结果**: ✅ 代码更易理解和维护
