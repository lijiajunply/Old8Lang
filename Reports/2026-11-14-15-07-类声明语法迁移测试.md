# 阶段 2「类声明语法迁移」测试报告

日期：2026-11-14 15:07

## 1. 本批改动

| 变化 | 说明 |
|------|------|
| `ClassSyntax`（Syntax） | 类/接口/混入声明的纯语法模型：类名、类体、父类、mixin/接口列表、抽象/接口/mixin 标志、泛型参数、文档注释 |
| `ClassInit`（Syntax） | 从 Runtime 迁入 Syntax，构造参数改为 `ClassSyntax`；`AnyValue`/`RegisterTypeToTypeSystem` 转为 Runtime 扩展 |
| `ClassFuncInitStatement`（Syntax） | 改存 `ClassMemberId + FunctionSyntax`；`FuncValue` 改为 `GetFuncValue()`（`ConditionalWeakTable` 缓存） |
| 运行时适配 | `ClassSyntaxRuntimeFactory` 用类体收集成员并创建 `TypeTemplate`；`GetTypeTemplate()` 按语法节点缓存；`CreateForTemplate` 支持嵌套类重算时覆盖模板 |
| 解析器 | `ClassParser` 不再构造 `TypeTemplate`，只构造 `ClassSyntax`；抽象方法/带修饰符方法改用 `FunctionSyntax` |
| 类执行辅助 | 590 行 `ClassInit.Split.cs` 转为 `ClassInitRuntimeExtensions` 扩展类；`OperatorNames` 移到辅助类 |
| 消费者更新 | 解释器/编译器/字节码 Visitor、VM 嵌套类重算、块成员收集、LSP 与测试改用 `GetTypeTemplate()`/`GetFuncValue()` |
| 生成代码 | Runtime 节点 55 → 54，遗留 partial 基线 9 → 8 |

## 2. 设计与兼容说明

- `ClassInit` 的 `TypeTemplate` 原先在解析期创建；现在改为首次访问 `GetTypeTemplate()` 时创建并缓存。
  由于类体成员收集会调用 `FuncInit.GetFuncValue()`（同样缓存），装饰器/文档注释与函数值身份保持一致。
- 字节码/执行辅助需要为“完整限定名的嵌套类”重新创建 `ClassInit` 时，使用
  `ClassInitRuntimeExtensions.CreateForTemplate(template)` 并通过弱表绑定模板，避免再从空类体重建。
- `ClassInit.ToString()` 改为基于语法模型输出 `class X { ... }`；未发现测试或运行时依赖旧的多行成员展开格式。
