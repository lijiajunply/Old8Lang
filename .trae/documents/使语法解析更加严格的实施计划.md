# 使语法解析更加严格的实施计划

## 1. 问题分析
当前的语法解析器在遇到无法识别的语句类型时，会尝试跳过当前语句并继续解析，而不是直接报错。这种容错机制会导致语法错误被隐藏，不利于开发者编写正确的代码。

## 2. 修改点

### 2.1 修改 ParseStatement() 方法
- **文件**：`Old8Lang/LangParser/LangParser.cs`
- **位置**：第473-516行
- **修改内容**：
  - 移除跳过无法识别语句的逻辑
  - 当遇到无法识别的语句类型时，直接抛出语法错误
  - 确保所有语法错误都能被明确报告

### 2.2 移除或修改容错逻辑
- **文件**：`Old8Lang/LangParser/LangParser.cs`
- **修改内容**：
  - 检查并移除其他可能的容错逻辑
  - 确保解析器对语法错误零容忍

## 3. 测试计划

### 3.1 初始测试
- 运行现有的语法测试，了解当前测试覆盖情况
- 使用命令：`dotnet run --project Old8Lang.App -- -s <测试文件>`

### 3.2 边修改边测试
- 修改一部分代码后，运行相关的语法测试
- 确保修改后的解析器能够正确报告语法错误

### 3.3 全面测试
- 所有修改完成后，运行所有语法测试
- 使用 `run_syntax_tests.sh` 脚本进行全面测试

## 4. 预期效果
- 语法解析器将严格检查所有代码，任何语法错误都会被明确报告
- 开发者能够更快地发现和修复语法错误
- 提高代码质量和开发效率

## 5. 实施步骤
1. 运行初始语法测试

3. 测试修改后的解析器
4. 检查并修改其他可能的容错逻辑
5. 进行全面的语法测试
6. 记录测试结果

## 6. 风险评估
- 可能会导致一些原本能够"容忍"的代码现在报错
- 需要确保测试用例覆盖各种语法场景
- 修改后需要仔细测试，确保不会破坏现有功能
