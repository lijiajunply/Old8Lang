## 模式说明

- **解释器模式** (`-f`): 直接执行代码，无需编译
- **IL 模式** (`-il`): 编译为 IL 中间代码再执行
- **虚拟机模式** (字节码): 编译为字节码后在虚拟机中执行

## 支持标记

- ✅ **完全支持**: 功能已实现且测试通过
- ⚠️ **部分支持**: 功能基本可用但有限制
- ❌ **不支持**: 功能未实现
- 🚧 **开发中**: 功能正在开发

**标记格式**: `[解释器 | 编译器 | 虚拟机]`

## 总结

### 解释器模式 (`-f`)
- **支持度**: 最高（几乎所有特性）
- **优点**: 功能最完整，支持所有高级特性
- **缺点**: 性能较低
- **适用场景**: 开发调试、快速原型、使用高级特性

### IL 模式 (`-il`)
- **支持度**: 高（大部分特性）
- **优点**: 性能较高，类型安全
- **缺点**: 需要完整类型注解，部分高级特性不支持
- **适用场景**: 生产环境、性能要求高的场景
- **限制**: 不支持泛型、部分异步特性、extern Python

### 虚拟机模式 (字节码)
- **支持度**: 高（基础特性、高级类型、泛型函数、异步、预编译指令均已实测可用）
- **优点**: 支持序列化、跨平台、独立运行、模块化
- **适用场景**: 嵌入式环境、需要序列化的场景、模块化应用
- **限制**（2026-10-08 实测，详见 [MODE_COMPLETION_STATUS.md](./MODE_COMPLETION_STATUS.md) 的「虚拟机模式」已知限制）:
  - ✅ 闭包写回外层**局部**变量：2026-10-09 起由共享单元（`UpValueCell`）支持，闭包与外层双向可见
  - ❌ 函数装饰器（被静默绕过）
  - ⚠️ 静态类 API：`Task.Delay`/`WhenAll`/`WhenAny`/`Run`/`StartNew` 等、`Thread.Sleep`、`Assert` 的断言方法可用；
    `Task.Factory`、`Thread.CurrentThread`、TestRunner / Mock / TaskScheduler / TaskCompletionSource 仍报 `VM_UNSUPPORTED_ERROR`
  - ✅ 原生 C 库导入调用（2026-10-09 实测：三种调用约定、批量/单函数导入、缺库缺符号报错）；Python / JavaScript / C# DLL 未验证
  - ❌ 泛型类（泛型函数可用，但需显式类型参数）
  - ⚠️ 直接 `print` 集合输出 .NET 类型名（`.ToStr()` 正常）
  - ✅ 无返回值调用参与表达式（`r <- f()`、`print(f())`）的求值栈一致性已于 2026-10-08 修复
  - ⚠️ 原生函数无法区分"无返回值"与"null"：`print(Sleep(1))` 在虚拟机输出 `null`，解释器不输出

### 推荐使用策略

1. **开发阶段**: 使用解释器模式 (`-f`)，享受完整功能和快速迭代
2. **生产部署**: 使用 IL 模式 (`-il`)，获得更好的性能和类型安全
3. **嵌入式/序列化**: 使用虚拟机模式，但需注意功能限制

### 未来计划

原计划中列出的以下几项经 2026-10-08 实测**已经可用**，不再属于待开发项：
Lambda 表达式、字符串模板、可空类型、类型转换、预编译指令、`async`/`await`。
（Match 表达式因文档示例本身写法有误，本次未能判定。）

- 🚧 TestRunner / Mock / TaskScheduler / TaskCompletionSource / CancellationTokenSource 静态类；
  🚧 `Task.Factory`、Task 实例方法 `Then/Catch/Finally/ContinueWith`（`Task`/`Thread`/`Assert` 的其余静态 API 已于 2026-10-08 支持）
