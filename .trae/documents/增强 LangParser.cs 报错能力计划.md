# 增强 LangParser.cs 报错能力计划

## 1. 分析当前错误处理机制

### 1.1 现有错误类结构
- `Old8Exception`：错误基类，包含错误代码、位置信息、建议等
- `SyntaxError`：语法错误类，继承自 `Old8Exception`
- `RuntimeError`：运行时错误类，继承自 `Old8Exception`

### 1.2 当前错误处理流程
- 在解析过程中，遇到语法错误时抛出 `SyntaxError`
- 错误信息包含位置信息（行号、列号）
- 但缺乏上下文信息和友好的修复提示

## 2. 增强错误处理机制设计

### 2.1 增强错误类
- 添加错误类型枚举：`SyntaxError`、`SemanticError`、`FormatError` 等
- 扩展 `Old8Exception`，添加上下文信息字段
- 添加修复建议字段，为常见错误提供具体修复指导

### 2.2 实现上下文信息收集
- 在 `SyntaxError` 构造函数中添加上下文信息参数
- 实现代码片段提取逻辑，获取错误位置前后的若干行代码
- 在报错时显示代码片段，并标注错误位置

### 2.3 增强错误信息格式
- 确保错误信息包含：
  - 错误类型
  - 错误位置（文件名、行号、列号）
  - 错误描述
  - 上下文代码片段
  - 修复建议
- 使用结构化格式，便于调试工具解析

## 3. 具体修改步骤

### 3.1 修改 Old8Exception 类
- 添加 `ErrorType` 枚举属性
- 添加 `ContextLines` 字段，存储上下文代码片段
- 添加 `FixSuggestion` 字段，存储修复建议

### 3.2 修改 SyntaxError 类
- 扩展构造函数，支持上下文信息和修复建议
- 实现代码片段提取逻辑

### 3.3 修改 LangParser.cs
- 在 `Expect` 方法中增强错误信息
- 为所有 throw 语句添加详细的错误描述和修复建议
- 在解析关键语法结构时，添加更细粒度的错误处理
- 实现上下文信息收集，获取错误位置附近的代码

### 3.4 实现友好的错误提示
- 为常见错误类型添加具体的修复建议
- 例如：
  - 缺少括号："缺少右括号，请检查语法结构"
  - 无效标识符："无效的标识符，请检查变量名拼写"
  - 类型不匹配："类型不匹配，期望整数类型"

### 3.5 确保调试工具兼容性
- 使用标准的异常处理机制
- 确保错误信息格式符合调试工具的预期
- 保留原始异常信息，便于调试

## 4. 测试验证

### 4.1 编写测试用例
- 语法错误测试：缺少括号、无效标识符、语法结构错误等
- 语义错误测试：类型不匹配、未定义变量等
- 边界情况测试：空文件、特殊字符、超长行等
- 特殊语法测试：lambda 表达式、复杂嵌套结构等

### 4.2 验证错误信息
- 检查错误位置是否准确
- 检查上下文信息是否显示正确
- 检查错误类型分类是否清晰
- 检查修复建议是否友好有效

### 4.3 验证调试工具兼容性
- 使用 IDE 调试功能验证错误捕获
- 检查错误信息在调试工具中的显示效果

## 5. 预期效果

### 5.1 错误信息示例
```
语法错误 (SYNTAX_ERROR)
位置: test.old8:10:5
错误描述: 缺少右括号
上下文:
  8 | func test() {
  9 |     var x <- 10
 10 |     return x
    |         ^ 错误位置
 11 | }
修复建议: 检查函数定义，确保所有括号匹配
```

### 5.2 错误类型分类
- **语法错误**：语法结构不符合规范
- **语义错误**：语法正确但语义有误（如类型不匹配）
- **格式错误**：代码格式不符合约定
- **其他错误**：无法分类的错误

- 支持上下文代码展示
- 确保调试工具兼容性
