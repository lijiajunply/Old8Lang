## 问题描述

### 1. ToStr()方法在字符串拼接中返回错误值

**现象**:
```old8lang
a <- 123
PrintLine("值: " + a.ToStr())  // ❌ 输出: "值: 988495328"（错误的内存地址）
result <- a.ToStr()
PrintLine(result)               // ✅ 输出: "123"（正确）
```

**根本原因**:
- ToStr()在赋值语句中工作正常，但在字符串拼接表达式中失败
- 问题出在`Operation.OutputType(LocalManager local)`方法（不带IL生成的版本）
- 该方法只处理了`Right is LangId`的情况（第354-373行），没有处理`Right is Instance`
- 导致Plus操作符无法正确识别`a.ToStr()`的返回类型为string
- 编译器错误地将字符串拼接当作数值加法处理，导致错误结果

**详细分析**:

执行 `"值: " + a.ToStr()` 时的调用流程：
1. 外层Plus操作调用`OutputType(ilGenerator, local)`生成IL
2. 第394-395行调用`Right?.OutputType(local)`（无IL版本）获取右操作数类型
3. `a.ToStr()`的`OutputType(local)`被调用
4. 但该方法没有处理Instance类型的Right，返回了错误的类型（int而非string）
5. 第432行的类型判断失败：`if (leftType == typeof(string) || rightType == typeof(string))`
6. 未进入字符串拼接分支，而是进入了数值加法分支
7. 导致生成错误的IL代码

### 2. 嵌套字典索引访问失败

**现象**:
```old8lang
nestedDict <- {
    "person": {
        "name": "李四",
        "age": 30
    }
}
PrintLine("姓名: " + nestedDict["person"]["name"])  // ❌ 编译错误
```

**错误信息**:
```
[INVALID_OPERATION_ERROR] 类型 'Object' 不支持索引访问
at Operation.OutputType() line 1031
```

**根本原因**:
- `nestedDict["person"]` 返回`Object`类型（因为Dictionary<object,object>的值类型是object）
- 第二次索引`["name"]`尝试在Object类型上调用Item属性
- Object类型没有索引器，导致编译失败
- 需要运行时类型转换来处理这种动态类型场景

---

## 解决方案

### 修复1: 添加ToStr()的类型推断支持

**文件**: `Old8Lang/AST/Expression/Operation.cs`

在`OutputType(LocalManager local)`方法中添加对Instance的处理（第375-395行）：

```csharp
// 处理方法调用（Dot操作符 + Instance）
if (Opera == LangTokenType.Dot && Right is Instance instance)
{
    // 特殊处理ToStr()方法，返回string类型
    if (instance.Id.IdName == "ToStr" && instance.Ids.Count == 0)
    {
        return typeof(string);
    }

    // 对于其他方法调用，尝试查找方法并返回其返回类型
    if (leftType != null)
    {
        var paramTypes = instance.Ids.Select(id => id.OutputType(local) ?? typeof(object)).ToArray();
        var method = leftType.GetMethod(instance.Id.IdName, paramTypes);
        if (method != null)
        {
            return method.ReturnType;
        }
    }
    return typeof(object);
}
```

**关键点**:
- 特殊处理ToStr()，直接返回`typeof(string)`
- 对于其他方法，通过反射查找方法并返回正确的返回类型
- 提供fallback返回`typeof(object)`保证鲁棒性

### 修复2: 支持Object类型的动态索引访问

**文件**: `Old8Lang/AST/Expression/Operation.cs`

在Dot操作符的索引访问处理中，添加对Object类型的支持（第1019-1079行）：

```csharp
else if (leftType == typeof(object))
{
    // Object类型，可能是字典、列表或数组
    // 策略：先存储到局部变量，然后依次尝试类型转换

    // 保存rightValue到局部变量
    var rightLocal = ilGenerator.DeclareLocal(typeof(object));
    if (rightType.IsValueType)
    {
        ilGenerator.Emit(OpCodes.Box, rightType);
    }
    ilGenerator.Emit(OpCodes.Stloc, rightLocal);

    // 保存leftValue到局部变量
    var leftLocal = ilGenerator.DeclareLocal(typeof(object));
    ilGenerator.Emit(OpCodes.Stloc, leftLocal);

    var endLabel = ilGenerator.DefineLabel();
    var notDictLabel = ilGenerator.DefineLabel();
    var notListLabel = ilGenerator.DefineLabel();

    // 尝试Dictionary<object, object>
    ilGenerator.Emit(OpCodes.Ldloc, leftLocal);
    ilGenerator.Emit(OpCodes.Isinst, typeof(Dictionary<object, object>));
    ilGenerator.Emit(OpCodes.Dup);
    ilGenerator.Emit(OpCodes.Brfalse, notDictLabel);

    // 是Dictionary
    ilGenerator.Emit(OpCodes.Ldloc, rightLocal);
    var dictIndexer = typeof(Dictionary<object, object>).GetProperty("Item")!;
    ilGenerator.Emit(OpCodes.Callvirt, dictIndexer.GetGetMethod()!);
    ilGenerator.Emit(OpCodes.Br, endLabel);

    // 不是Dictionary，尝试List<object>
    ilGenerator.MarkLabel(notDictLabel);
    ilGenerator.Emit(OpCodes.Pop); // 弹出null
    ilGenerator.Emit(OpCodes.Ldloc, leftLocal);
    ilGenerator.Emit(OpCodes.Isinst, typeof(List<object>));
    ilGenerator.Emit(OpCodes.Dup);
    ilGenerator.Emit(OpCodes.Brfalse, notListLabel);

    // 是List
    ilGenerator.Emit(OpCodes.Ldloc, rightLocal);
    ilGenerator.Emit(OpCodes.Unbox_Any, typeof(int));
    var listIndexer = typeof(List<object>).GetProperty("Item")!;
    ilGenerator.Emit(OpCodes.Callvirt, listIndexer.GetGetMethod()!);
    ilGenerator.Emit(OpCodes.Br, endLabel);

    // 不是List，尝试object[]
    ilGenerator.MarkLabel(notListLabel);
    ilGenerator.Emit(OpCodes.Pop);
    ilGenerator.Emit(OpCodes.Ldloc, leftLocal);
    ilGenerator.Emit(OpCodes.Isinst, typeof(object[]));
    ilGenerator.Emit(OpCodes.Ldloc, rightLocal);
    ilGenerator.Emit(OpCodes.Unbox_Any, typeof(int));
    ilGenerator.Emit(OpCodes.Ldelem_Ref);

    ilGenerator.MarkLabel(endLabel);
    return typeof(object);
}
```

**IL生成策略**:
1. 将left和right值保存到局部变量（避免栈操作混乱）
2. 使用`isinst`指令尝试类型转换
3. 使用条件跳转指令实现类型判断分支：
   - 首先尝试`Dictionary<object, object>`
   - 失败则尝试`List<object>`
   - 再失败则尝试`object[]`
4. 每个分支调用对应的索引器方法
5. 使用label统一出口，确保栈平衡

**关键IL指令**:
- `Isinst`: 尝试将对象转换为指定类型，失败返回null
- `Dup`: 复制栈顶值，用于判断转换是否成功
- `Brfalse`: 如果栈顶为false/null，跳转到指定label
- `Stloc/Ldloc`: 存储/加载局部变量
- `Callvirt`: 调用虚方法（索引器的getter）

## 调试过程

### Bug 1: ToStr在字符串拼接中返回错误值

**调试步骤**:
1. 发现`result <- a.ToStr()`正常，但`"值: " + a.ToStr()`失败
2. 怀疑是字符串拼接的IL生成有问题
3. 检查Plus操作的IL生成，发现调用了`Right?.OutputType(local)`
4. 追踪到`OutputType(LocalManager)`方法
5. 发现该方法只处理`Right is LangId`，没有处理`Right is Instance`
6. 添加Instance处理分支，问题解决

**关键insight**: 类型推断有两个版本的方法，必须保持一致！

### Bug 2: 嵌套字典索引访问

**调试步骤**:
1. 错误信息指向Operation.cs:1031行
2. 发现是"类型 'Object' 不支持索引访问"
3. 分析：`nestedDict["person"]`返回Object类型
4. 第二次索引`["name"]`在Object上查找Item属性失败
5. 需要添加运行时类型转换
6. 实现了基于isinst的动态类型分发
7. 使用局部变量和label确保栈平衡

**关键insight**: 动态类型需要运行时类型检查，不能依赖编译时类型信息！
