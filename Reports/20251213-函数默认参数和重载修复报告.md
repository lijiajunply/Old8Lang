## 问题描述

### 1. 函数默认参数不支持

**现象**:
```old8lang
func greet(name, message: "Hello") {
    PrintLine(message + ", " + name + "!")
}

greet("Alice")  // ❌ 编译失败: InvalidProgramException
```

**原因**:
- 函数定义时生成了接受2个参数的DynamicMethod
- 函数调用时只传递了1个参数
- 参数数量不匹配导致方法查找失败

### 2. 函数重载不支持

**现象**:
```old8lang
func test(a) {
    PrintLine("单参数")
}

func test(a, b) {
    PrintLine("双参数")
}

test(1)     // ❌ 只输出"双参数"
test(1, 2)  // ✅ 输出"双参数"
```

**原因**:
- 多个同名函数使用相同的键存储在DelegateVar中
- 后定义的函数覆盖了先定义的函数
- 重载机制完全失效

---

## 解决方案

### 核心策略

使用 **"函数名$参数数量"** 作为函数的唯一标识符，支持同名但不同参数数量的函数共存。

### 实现细节

#### 1. 扩展LocalManager存储函数参数信息

**文件**: `Old8Lang/Compiler/LocalManager.cs`

添加新的字典存储函数的参数列表：

```csharp
// 存储函数的参数列表信息（用于支持默认参数）
public readonly Dictionary<string, List<LangId>> FuncParameters = [];
```

这样可以在编译时查询函数的默认参数信息。

#### 2. 修改函数注册逻辑

**文件**: `Old8Lang/AST/Statement/FuncInit.cs` 和 `Old8Lang/AST/Expression/Value/FuncLangValue.cs`

修改函数注册时的键生成策略：

```csharp
// 使用函数名+参数数量作为键，支持函数重载
var delegateKey = methodName;
if (FuncLangValue.Ids != null)
{
    delegateKey = $"{methodName}${FuncLangValue.Ids.Count}";
}
local.DelegateVar.TryAdd(delegateKey, dynamicMethod);

// 同时存储函数的参数列表信息
if (FuncLangValue.Ids != null)
{
    local.FuncParameters.TryAdd(delegateKey, FuncLangValue.Ids);
}
```

**示例**:
- `func add(a, b)` → 键为 `add$2`
- `func add(a)` → 键为 `add$1`
- `func greet(name, msg: "Hi")` → 键为 `greet$2`

#### 3. 增强函数查找逻辑

**文件**: `Old8Lang/AST/Expression/Value/Instance.cs`

在`LoadIlValue`方法中，实现智能函数查找：

```csharp
// 首先尝试使用方法名+参数数量查找（支持重载）
// 对于带默认参数的情况，从实际参数数量开始，逐步增加参数数量尝试匹配
for (int paramCount = Ids.Count; matchingMethod == null && paramCount <= Ids.Count + 10; paramCount++)
{
    var delegateKey = $"{Id.IdName}${paramCount}";

    if (local.DelegateVar.TryGetValue(delegateKey, out var result))
    {
        // 获取函数的参数列表信息
        local.FuncParameters.TryGetValue(delegateKey, out funcParams);

        var methodParams = result.GetParameters();

        // 检查参数数量是否匹配
        if (methodParams.Length == Ids.Count)
        {
            // 完全匹配
            matchingMethod = result;
            break;
        }
        else if (funcParams != null && Ids.Count < methodParams.Length)
        {
            // 参数数量少于方法参数，检查是否有默认参数可以补充
            // 计算必需参数的数量
            int requiredParamsCount = 0;
            for (int i = 0; i < funcParams.Count; i++)
            {
                if (funcParams[i].DefaultValue == null)
                {
                    requiredParamsCount++;
                }
            }

            // 如果实际参数数量大于等于必需参数数量，则可以匹配
            if (Ids.Count >= requiredParamsCount)
            {
                matchingMethod = result;
                break;
            }
        }
    }
}
```

**查找策略**:
1. 从实际参数数量开始查找 `函数名$N`
2. 逐步增加N，尝试找到带默认参数的重载
3. 验证必需参数数量，确保可以使用默认参数补充
4. 找到第一个匹配的函数后立即返回

#### 4. 补充默认参数值的IL生成

在找到匹配的函数后，如果实际参数少于函数参数，需要补充默认参数的IL代码：

```csharp
// 如果有默认参数需要补充
if (funcParams != null && Ids.Count < matchingParams.Length)
{
    // 补充默认参数值
    for (var i = Ids.Count; i < funcParams.Count; i++)
    {
        var param = funcParams[i];
        if (param.DefaultValue != null)
        {
            // 加载默认参数值
            param.DefaultValue.LoadIlValue(ilGenerator, local);

            // 确保类型匹配
            var paramType = matchingParams[i].ParameterType;
            var defaultType = param.DefaultValue.OutputType(local);

            if (defaultType != null && paramType != defaultType)
            {
                // 类型转换逻辑...
            }
        }
    }
}
```

#### 5. 修复OutputType方法

**关键bug修复**：`Instance.OutputType`方法也需要使用相同的查找策略，否则返回类型推断会失败。

```csharp
public override Type OutputType(LocalManager local)
{
    // ... switch cases for built-in functions ...

    // 尝试使用函数名+参数数量查找（支持重载）
    var delegateKey = $"{Id.IdName}${Ids.Count}";
    var result = local.DelegateVar.GetValueOrDefault(delegateKey);

    // 如果找不到，可能是带默认参数的函数
    if (result == null)
    {
        for (int paramCount = Ids.Count + 1; paramCount <= Ids.Count + 10; paramCount++)
        {
            delegateKey = $"{Id.IdName}${paramCount}";
            result = local.DelegateVar.GetValueOrDefault(delegateKey);

            if (result != null)
            {
                // 检查是否有默认参数支持这个调用
                if (local.FuncParameters.TryGetValue(delegateKey, out var funcParams))
                {
                    int requiredParamsCount = 0;
                    for (int i = 0; i < funcParams.Count; i++)
                    {
                        if (funcParams[i].DefaultValue == null)
                        {
                            requiredParamsCount++;
                        }
                    }

                    if (Ids.Count >= requiredParamsCount)
                    {
                        break; // 找到匹配的函数
                    }
                }
                result = null; // 参数不匹配，继续查找
            }
        }
    }

    if (result != null) return result.ReturnType;

    var classType = local.ClassVar.GetValueOrDefault(Id.IdName);
    return classType ?? typeof(object);
}
```

**这个修复至关重要**！在调试过程中发现，当函数返回值被赋值给变量时（如`r <- add(1, 2)`），会先调用`OutputType`获取返回类型，再生成赋值的IL代码。如果`OutputType`找不到函数返回null或object类型，会导致后续IL生成错误。

## 调试过程

### Bug 1: InvalidProgramException

**现象**: 简单默认参数测试编译失败
```
System.InvalidProgramException: Common Language Runtime detected an invalid program.
```

**原因**: 函数注册键生成逻辑有误，零参数函数未正确处理

**解决**: 统一使用`$"{methodName}${Ids.Count}"`，即使Ids.Count=0也使用此格式

### Bug 2: NullReferenceException

**现象**: 函数调用返回值赋值时崩溃
```csharp
r <- add(1, 2)  // ❌ NullReferenceException
add(1, 2)       // ✅ 正常工作
```

**原因**: `Instance.OutputType`方法仍使用旧的查找逻辑（`Id.IdName`），找不到函数返回类型

**解决**: 修改`OutputType`使用与`LoadIlValue`相同的查找策略

### Bug 3: 函数重载覆盖

**现象**: 后定义的重载覆盖先定义的重载

**原因**: 使用`TryAdd`时，相同的键无法添加第二次

**解决**: 使用参数数量作为键的一部分，确保每个重载有唯一的键

1. **默认参数位置**
   - 目前支持任意位置的默认参数
   - 但推荐将默认参数放在参数列表末尾（符合一般编程习惯）

2. **重载数量**
   - 理论上支持无限个重载
   - 实际上受字典大小限制（非常大）

3. **默认参数查找范围**
   - 当前限制为最多查找10个额外参数（Ids.Count到Ids.Count+10）
   - 对于绝大多数场景足够
