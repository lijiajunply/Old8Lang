## 2. 修复清单（陈旧写法 → 现行 API）

### 2.1 线程用例（8 个文件，补 `Start()`）

`spawn` 自 2026-10 起明确为「只创建线程，必须再 `Start()` 才会执行」，而
`Then` / `WithTimeout` / `Retry` 返回的同样是**未启动**的新线程。以下文件全部缺 `Start()`，
统一补上（链式写法 `spawn(f).Retry(n).Join()` 改为「先取线程 → Start → Join」）：

`test_thread_basic.old8`、`test_thread_simple.old8`、`test_thread_comprehensive.old8`、
`thread_advanced_features.old8`、`thread_retry_test.old8`、`ThreadSafetyTest.old8`、
`Async/LockThreadTest.old8`、`Async/LockVariableTests.old8`

顺带：

- `thread_advanced_features.old8` 里 `e.ToString()` → `e.ToStr()`（异常值没有 `ToString` 实例方法）。
- 该文件此前 `WithTimeout` 用例其实是**假通过**（见 §3），修完后真的会超时并被捕获。

## 3. 顺带修掉的实现缺陷

### 3.1 `super.method(args)` 被误当成父类构造函数（解释器）

- **根因**：`Old8Lang/AST/Expression/Core/SuperExpression.cs` 的 `SuperProxy.Dot` 对任何
  `super.xxx(...)` 都调用 `CallParentConstructor`（只查父类的 `init`/类名方法）。
- **表现**：父类有 `init` 时 `super.speak()` 会去调 `init` 并报「参数 'n' 缺少实参」；
  父类没有 `init` 时静默返回 `null`，随后 `super.speak() + "B"` 报
  `不支持类型 'NullLangValue' 和 'StringLangValue' 的加法操作`。
- **修复**：只有 `super.init(...)` / `super.父类名(...)` 走构造函数，其余按普通父类方法
  （新增 `CallParentMethod`，用父类方法表按名查找 + `SelectMethod` 处理重载）。

实测：

```
$ cat probe3.old8     # class A { func speak() -> string { return "A" } } / B.speak() = super.speak() + "B"
$ ... -f probe3.old8  → AB / name-A!        （修前：加法类型错误）
$ ... -f probe4.old8  → A:hiB               （带参父类方法）
```

4 个 `super` 用例（`test_super_expression` / `test_super_debug` / `test_super_debug2` /
`test_super_simple`）现在全部通过；`Interpreter.Classes|Super|Inheritance` 过滤单测
**152 通过 / 17 失败**，17 个失败全部在基线失败集合内（既有 IL 缺陷），**无新增失败**。

### 3.2 顺带修好的线程组合方法（上一轮已记，本轮被用例验证）

- `ThreadLangValue.Then` 现在会 `Start()` continuation 返回的线程；
- `ThreadLangValue.WithTimeout` 改为真正带超时（超时抛 `TimeoutException`），此前只是起了个
  定时器却仍然无限等待（`thread_advanced_features.old8` 的「超时测试」因此是假通过）。
