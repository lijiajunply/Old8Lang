# 阶段 3.10 VM 引擎与字节码编译器迁入 VM 后端

日期：2026-11-14 17:20  
范围：[plan.md](../Docs/architecture-migration/plan.md) 阶段 3 的字节码/VM 引擎余量。

## 改动

1. VM 执行引擎从 `Old8Lang.Runtime/Bytecode/VM/` 迁入 `Old8Lang.VirtualMachine/VM/`：
   - `VirtualMachine` 全部 partial（Core、Instructions、Helpers、Tooling、Async、Generators 等）；
   - 字节码生成器值 `Bytecode/Generators/`（`BytecodeGeneratorLangValue` 等）。
2. Runtime 新增两个最小契约：
   - `IVirtualMachine`（`Bytecode.Core`）：全局变量、常量池、函数调用与工作线程执行；
   - `IBytecodeCompiler`（`Bytecode.Core`）：标记 Runtime 与具体字节码编译器之间的边界。
   `VMContext.CurrentVM` 改为 `IVirtualMachine?`，`VMReflectionHelper` 全部签名改为
   `IVirtualMachine`；`BytecodeCompiler` 实现 `IBytecodeCompiler`，VM 注册入口负责具体类型转换。
3. 字节码编译与运行支撑迁入 `Old8Lang.VirtualMachine/Bytecode/`：
   - `BytecodeCompiler`；
   - `ModuleSystem`（模块加载/注册，仅 `ModuleDependency`/`ExportedSymbol` 作为格式类型留在 Runtime）；
   - `Interop`（`ExternFunctionWrapper`）、`Debugger`（`VMDebugger`）、`Profiler`（`VMProfiler`）、
     `VmStaticClassRegistry`。
4. Runtime 的 `Bytecode/` 只保留格式与共享执行模型：
   - `BytecodeFile` 序列化、`Core`（指令、操作码、调用帧、`VMContext`、契约）、
     `Metadata`、`Closures`。
5. `GlobalSlot`/`VMTypeMapper` 因被 Runtime 的 `Instruction` 与实例方法直接引用，保留在
   Runtime（命名空间不变），由 VM 通过 friend assembly 复用。

## 验证

构建（`/usr/local/share/dotnet/dotnet build Old8Lang.sln`）：0 错误。

| 测试组 | 结果 |
| --- | --- |
| Architecture | 60 通过 |
| VirtualMachine（含字节码往返、模块、调试/分析） | 1083 通过 |
| Interpreter（排除 NetLibTests） | 1959 通过，1 跳过 |
| Compiler.Expressions | 179 通过，41 失败；与 HEAD 基线逐项一致 |

新增架构门禁：`VirtualMachine` 与 `BytecodeCompiler` 必须位于 `Old8Lang.VirtualMachine`；
`IVirtualMachine`/`IBytecodeCompiler`、`BytecodeFile`/`Instruction`/`FunctionMetadata` 必须位于
Runtime；Runtime 不再包含 VM 引擎源码。

## 遗留

- `Compiler/` IL 引擎（`Compiler.Compile`、特化/验证辅助）与运行时值 partial 仍在 Runtime。
- 解释期作用域状态（`VariateManager`、`ScopeLayer` 等）仍在 Runtime。
- 阶段 3 的「引擎余量」尚未清零，阶段 3 不标记完成。
