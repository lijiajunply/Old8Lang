## 问题概述

在编译模式下，void 函数的 return 语句生成的 IL 代码不正确，导致 `InvalidProgramException` 异常。

### 影响范围
- `Old8Lang.Tests.Compiler.Statements.JumpTests.Return_VoidFunction_ReturnsNothing` 测试失败
- 所有使用 void 返回类型的函数无法正常编译执行

---

## 问题表现

### 测试代码
```old8

### 预期行为
```

### 实际错误
抛出 `InvalidProgramException` - IL 代码无效

## 根本原因

问题根源在 `Old8Lang/AST/Statement/ReturnStatement.cs`。

### 错误代码（修复前）
```csharp
// 第44-68行（原版本）
var returnType = returnExpression.OutputType(local);
returnExpression.LoadIlValue(ilGenerator, local);

// ❌ 错误：假设所有函数都是异步函数
if (returnType != typeof(Task<object>))
{
    // 将所有返回值包装为 Task<object>
    if (returnType != null && returnType != typeof(object))
    {
        ilGenerator.Emit(OpCodes.Box, returnType);
    }

    var fromResultMethod = typeof(Task)
        .GetMethod("FromResult", ...)!
        .MakeGenericMethod(typeof(object));
    ilGenerator.Emit(OpCodes.Call, fromResultMethod);
}

ilGenerator.Emit(OpCodes.Ret);
```

### 问题分析
1. 代码错误地假设所有函数都是异步函数
2. 对于 void 函数的 `return` 语句：
   - `returnExpression` 为空或返回 void
   - 但代码仍尝试将其包装为 `Task<object>`
   - 导致栈上存在不正确的值类型
   - 函数签名期望 void，但栈上有 `Task<object>`
3. IL 验证失败，抛出 `InvalidProgramException`

## 修复方案

### 修复代码
```csharp
// Old8Lang/AST/Statement/ReturnStatement.cs:33-59
public override void GenerateIl(ILGenerator ilGenerator, LocalManager local)
{
    // 检查是否在finally块中使用了return语句
    if (local.IsInFinallyBlock)
    {
        throw new Error.CompilerException("在finally块中不允许使用return语句", Position);
    }

    // 获取返回值表达式的类型
    var returnType = returnExpression.OutputType(local);

    // 加载返回表达式的值到栈上
    returnExpression.LoadIlValue(ilGenerator, local);

    // ✅ 修复：只有异步函数才需要 Task 包装
    // 同步函数（包括 void 函数）直接返回值，不进行任何包装
    if (returnType == typeof(Task<object>))
    {
        // 异步函数：返回值已经是 Task<object>，直接返回
        ilGenerator.Emit(OpCodes.Ret);
    }
    else
    {
        // 同步函数：直接返回栈上的值
        // 对于 void 函数，栈上没有值，直接 Ret
        ilGenerator.Emit(OpCodes.Ret);
    }
}
```

### 修复说明
1. **移除错误的 Task 包装逻辑**：不再假设所有函数都是异步的
2. **同步函数直接返回**：包括 void 函数和有返回值的函数
3. **异步函数保持不变**：返回类型为 `Task<object>` 的函数继续正常工作

## 技术细节

### IL 代码生成流程（修复后）

**void 函数的 return 语句**:
1. `returnExpression` 为空或返回 void 类型
2. `LoadIlValue()` 不加载任何值到栈上（或加载后立即丢弃）
3. 直接发出 `OpCodes.Ret` 指令
4. 栈保持平衡，IL 验证通过

**有返回值的同步函数**:
1. `returnExpression` 加载返回值到栈上
2. 返回值类型匹配函数签名
3. 直接发出 `OpCodes.Ret` 指令
4. 调用者从栈上获取返回值

**异步函数（保持不变）**:
1. `returnExpression` 返回 `Task<object>` 类型
2. 直接发出 `OpCodes.Ret` 指令
3. 返回 Task 对象给调用者

## 总结

void 函数 IL 生成问题已通过修复 `ReturnStatement.GenerateIl()` 方法完全解决。修复的核心思想是：

1. **移除错误的假设**：不再假设所有函数都是异步的
2. **区分同步和异步**：只有 `Task<object>` 返回类型才是异步函数
3. **简化处理逻辑**：同步函数（包括 void）直接返回栈上的值

这个修复不仅解决了 void 函数问题，还作为问题5的一部分，整体改善了编译器的函数返回值处理机制。
