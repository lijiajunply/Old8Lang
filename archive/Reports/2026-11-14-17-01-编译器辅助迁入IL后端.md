# 阶段 3.5 编译器专用 IL 辅助迁入 IL 后端

日期：2026-11-14 17:01  
范围：[plan.md](../Docs/architecture-migration/plan.md) 阶段 3 的引擎余量，本轮先迁移不依赖运行时 partial 的编译器代码。

## 改动

从 `Old8Lang.Runtime` 迁入 `Old8Lang.Compiler`：

1. `Execution/OperationHelpers/` 中仅被 IL 后端使用的六个运算辅助（约 1800 行）：
   - `ComparisonOpHelper`、`LogicalOpILHelper`、`InOperatorHelper`、
     `NullishCoalescingILHelper`、`NumericBinaryOpHelper`、`TypeCheckILHelper`。
   - 保留 `DotOperatorILHelper`：Runtime 的 `TypeInferenceVisitor` 仍调用其中的
     `InferInstanceMethodReturnType`，待拆出共享类型解析后再迁。
2. LINQ 的 IL 生成（约 1200 行）：
   - `LinqExpression.Compiler.cs`、`LinqExpression.StreamingCompiler.cs`、
     `LinqExpressionRuntimeExtensions.cs`。
   - `CanGenerateStreamingQuery` 同时被 Runtime 类型推断与 IL 后端使用，保留在
     `Old8Lang.Runtime/AST/Expression/Linq/LinqExpressionStreamingAnalysis.cs`；
     IL 生成代码通过 friend assembly 访问该内部扩展。

命名空间保持不变，`CompilerVisitor` 与既有 `using` 无需修改；Runtime 不再包含这些
IL 发射实现，编译器程序集通过 `InternalsVisibleTo` 复用 Runtime 的 `LocalManager`
等共享编译契约。

## 验证

构建（`/usr/local/share/dotnet/dotnet build Old8Lang.sln`）：0 错误。

| 测试组 | 结果 |
| --- | --- |
| Architecture | 55 通过 |
| VirtualMachine | 1083 通过 |
| Interpreter（排除 NetLibTests） | 1959 通过，1 跳过 |
| Compiler.Expressions | 179 通过，41 失败；与 HEAD 基线逐项一致 |

`Linq` 与运算辅助的行为由 `Compiler.Expressions` 中的比较、逻辑、算术与 LINQ 用例覆盖；
失败项与迁移前完全相同，未引入新的编译差异。

## 遗留

- `DotOperatorILHelper` 仍留在 Runtime，需先将其中的实例方法返回类型解析抽成共享
  `InstanceMethodTypeResolver`，再迁 IL 发射部分。
- `Compiler/` 引擎（`Compiler.Compile`、`GlobalVariableAnalysis`、特化/验证辅助）与
  运行时值上的 `FuncLangValue.Compiler` partial 仍交织，完整迁出需要先把 partial 改为扩展方法。
- 解释与 VM 引擎余量同前；阶段 3 不标记完成。
