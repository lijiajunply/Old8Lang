# 阶段 2「简单调用语法迁移」测试报告

日期：2026-11-14 15:35
范围：`Docs/architecture-migration/plan.md` §2 的增量：解析器 `Instance` → Syntax `CallExpression`
状态：本批完成；阶段 2 整体未完成（`ImportStatement`、`LinqExpression`、解析器整体仍待拆分）。

## 1. 背景与设计

解析器对 `identifier(...)` 直接构造运行时 `Instance`，是解析器最后一个高频 Runtime 依赖。首次尝试
（第 5 轮）只做节点替换，导致 `File.CreateDirectory(x)` 等点号调用被 `Dot` 实现当成属性访问：
`AnyLangValue.Dot`、`UnifiedModule.Dot`、`SuperProxy`、IL Dot 辅助等都以“右侧是 `Instance`”作为
方法调用判据。该尝试已完整回退。

本批采用**归一化适配**方案：

| 变化 | 说明 |
|------|------|
| `CallExpression`（Syntax） | 承载标识符、位置参数、命名参数与位置；`Accept` 走 `IVisitor` |
| 运行时适配 | `CallExpressionRuntimeExtensions.ToInstance` 创建等价 `Instance`；`CallSyntaxAdapter.Normalize` 把调用语法归一化为 `Instance` |
| 解释器 | `VisitOperation` 的 Dot 分支先归一化右操作数，所有既有 `is Instance` 分支继续生效 |
| 字节码 | Dot 分支同样归一化；静态类访问 `TryCompileStaticClassAccess` 先归一化再匹配方法调用 |
| IL 编译器 | `DotOperatorILHelper.GenerateDotOperator` 接收归一化后的右操作数 |
| 类型推断 | `VisitOperation` 的 Dot 分支归一化；`GenericTypeInference.InferArgumentType` 对调用语法按 `Instance` 处理 |
| VM 闭包 | `ClosureCaptureAnalyzer` 识别 `CallExpression` 的调用名与实参；Dot 方法调用参数同样分析 |
| LSP | 构造函数调用与成员方法调用分析同时接受 `Instance`、`CallExpression` |
| 解析器 | `ParseInstantiate` 与语句级函数调用改为 `CallExpression`；独立调用语句识别同时接受两种节点 |

## 2. 测试修复过程

1. 首次恢复节点替换后，Interpreter 617 项、VM 596 项失败（Dot 调用退化）。
2. 加入 Dot 归一化后：Interpreter 2 项（泛型推断）、VM 65 项（静态类 `Assert.*`、装饰器闭包）。
3. 修复泛型推断与静态类归一化后：VM 16 项（装饰器捕获 `f()`）。
4. 修复闭包捕获分析后：VM 全通过；LSP 12 项（成员链/构造调用分析），修复后全通过。
