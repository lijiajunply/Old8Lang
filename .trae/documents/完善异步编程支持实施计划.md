# 完善异步编程支持实施计划

## 1. 目标
解决 `TODO_Compiler.md` 中的高优先级任务：完善异步编程支持。具体目标是修复 `await` 在异步函数中的状态机生成问题，实现真正的异步状态机（使用 `AwaitUnsafeOnCompleted`），从而解决 "invalid program" 错误并支持非阻塞的异步执行。

## 2. 核心问题分析
当前的 `AsyncStateMachineGenerator` 和 `AwaitExpression` 实现存在以下问题：
1.  **假异步**: `AwaitExpression` 目前生成的是同步等待代码 (`GetAwaiter().GetResult()`)，这会导致线程阻塞。
2.  **状态机逻辑缺失**: `AsyncStateMachineGenerator` 虽然生成了状态机类结构，但 `MoveNext` 方法内部并没有实现真正的状态跳转和挂起逻辑，而是按顺序同步执行所有语句。
3.  **状态映射错误**: 现有的生成器将 "State" 映射为 "Statement Index"（语句索引），这是错误的。正确的映射应该是 "State" 对应 "Suspension Point"（挂起，即 `await` 表达式）。

## 3. 实施步骤

### 3.1 修改 `LocalManager.cs`
在 `LocalManager` 中添加对 `AsyncStateMachineGenerator` 的引用，以便 AST 节点（如 `AwaitExpression`）能够访问生成器并获取状态标签。

```csharp
public Generators.AsyncStateMachineGenerator? AsyncStateMachineGenerator { get; set; }
```

### 3.2 重构 `AsyncStateMachineGenerator.cs`
这是核心修改部分，需要进行大幅重构：
1.  **建立正确的状态映射**:
    *   维护 `Dictionary<AwaitExpression, int> AwaitStateMap`，将每个 `AwaitExpression` 映射到一个唯一的整数状态索引。
2.  **重构 `GenerateMoveNextMethod`**:
    *   不再循环遍历语句生成代码块。
    *   改为生成**一次**完整的函数体代码 (`BlockStatement.GenerateIl`)。
    *   在函数体开头生成 `Switch` 指令，用于跳转到各个 `await` 的恢复点（Resume Labels）。
3.  **提供辅助方法**:
    *   `GetAwaitLabel(AwaitExpression expr)`: 获取指定 `await` 表达式的恢复标签。
    *   `EmitAwaitYield(...)`: 生成挂起逻辑（保存状态、保存 awaiter、注册回调、Ret）。
    *   `EmitAwaitResume(...)`: 生成恢复逻辑（标记标签、恢复 awaiter、清除字段）。
    *   `EmitReturn(...)`: 生成异步完成逻辑（SetResult, SetState(-2), Ret）。

### 3.3 修改 `AwaitExpression.cs`
更新 `LoadIlValue` 方法以支持真正的异步生成：
1.  检查 `local.AsyncStateMachineGenerator` 是否存在。
2.  如果存在（在异步函数中）：
    *   获取当前表达式对应的 `StateIndex`。
    *   生成检查 `IsCompleted` 的代码。
    *   如果未完成，调用 `generator.EmitAwaitYield` 挂起执行。
    *   调用 `generator.EmitAwaitResume` 标记恢复点。
    *   调用 `GetResult` 获取结果。
3.  如果不存在（在同步上下文或顶层），保持原有的同步等待逻辑。

### 3.4 修改 `ReturnStatement.cs`
更新 `GenerateIl` 方法：
1.  检查 `local.AsyncStateMachineGenerator` 是否存在。
2.  如果存在，调用 `generator.EmitReturn` 来正确设置 Task 结果并完成状态机，而不是简单地发出 `Ret` 指令。

### 3.5 修改 `AsyncFuncInit.cs`
在生成 IL 时，将创建的 `AsyncStateMachineGenerator` 实例传递给 `LocalManager`，确保函数体内的 AST 节点能访问到它。

## 4. 风险与限制
*   **栈溢出风险**: 由于 `EmitAwaitYield` 会发出 `Ret` 指令，如果 `await` 表达式处于求值栈不为空的上下文中（例如 `f(1, await t)`，此时栈上有 `1`），直接 `Ret` 会导致栈数据丢失或运行时错误。
*   **应对策略**: 本次修复主要支持语句级和表达式级（栈为空时）的 `await`（如 `x <- await t`, `await t`, `return await t`）。对于复杂嵌套表达式中的 `await`，目前可能仍有限制，但这已覆盖绝大多数使用场景。
