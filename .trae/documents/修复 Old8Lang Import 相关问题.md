# 修复 Old8Lang Import 相关问题

## 问题分析

1. **缺少循环依赖检测**：当前导入机制没有检测循环依赖，可能导致无限递归导入
2. **Import 错误信息不够详细**：错误信息只包含模块名，缺乏上下文信息
3. **缺少模块缓存机制**：每次导入都重新解析执行，性能低下
4. **作用域隔离不完整**：模块变量直接添加到当前作用域，容易产生命名冲突

## 修复方案

### 1. 循环依赖检测
- 在 `VariateManager` 中添加 `ImportStack` 属性，记录当前导入路径
- 在 `ImportStatement.Run` 方法中，导入前检查模块是否已在导入栈中
- 导入时将模块路径压入栈，导入完成后弹出
- 发现循环依赖时抛出 `ImportError`，包含完整的循环依赖链

### 2. 详细 Import 错误信息
- 扩展 `ImportError` 类，添加更多上下文属性
- 在抛出错误时包含：
  - 模块名称
  - 尝试的文件路径列表
  - 导入来源文件
  - 行号和列号
- 改进错误信息格式，使其更易于调试

### 3. 模块缓存机制
- 在 `LangInterpreter` 中添加 `ModuleCache` 字典，缓存已解析的模块
- 缓存键为模块的绝对路径
- 缓存值包含解析后的 AST 和导出成员
- 在 `ImportStatement.Run` 和 `GenerateIl` 方法中优先使用缓存
- 支持缓存失效机制，便于开发调试

### 4. 作用域隔离
- 为每个模块创建独立的作用域
- 模块内部变量和函数仅在模块作用域内可见
- 只有显式导出的成员才能被外部访问
- 实现命名导入和默认导入机制
- 确保不同模块间的命名冲突得到解决

## 实现步骤

1. 修改 `VariateManager` 类，添加导入栈支持
2. 扩展 `ImportError` 类，增强错误信息
3. 在 `LangInterpreter` 中添加模块缓存
4. 修改 `ImportStatement` 类，实现循环依赖检测和缓存机制
5. 改进模块导入时的作用域处理
6. 编写测试用例验证修复效果
7. 更新文档说明新的导入机制

## 预期效果

- 导入循环依赖时能得到清晰的错误提示
- 导入错误信息包含足够的上下文，便于调试
- 模块导入性能提升，避免重复解析
- 模块间作用域隔离，减少命名冲突
- 支持更灵活的导入方式（命名导入、默认导入）
