# Old8Lang 项目现状与缺口排查（2026-10-23）

## 0. 结论摘要

- **构建绿、测试红**：`dotnet build Old8Lang.sln` 0 错误 / 400 警告；默认档 xUnit 中 IL（`Compiler`）用例 **737 失败**，且全量测试会在中途因栈溢出**直接中止**。
- **非 IL 模式基本健康**：解释器 / VM / LSP / 解析器 / 库测试共 4734 例，仅 1 例并行抖动、3 例跳过。
- **IL 模式是当前最大空洞**：不仅 xUnit 失败，164 个 `.old8` 用例里 94 个失败，其中 8 次是进程级崩溃（段错误 / Bus error）。
- **本次新发现 5 个 `Todo.md` 未记录的问题**，其中 2 个影响面很大：
  1. **顶层 `Assert.Equal(x, y)` 生成的 IL 非法**（可选参数 `message` 未补默认值，栈下溢）。IL 测试几乎全部在顶层用 `Assert.*` 断言，这很可能是 737 失败的最大单一来源。
  2. **IL 实例方法读取字段返回随机值**（`this.v` 读错，`m.v` 顶层读却正确）。
- 另外 3 个：IL 函数**无法访问顶层全局变量**、IL 模式**顶层语句被执行两次**、IL 打印布尔值输出 `True/False`（解释器/VM 为 `true/false`）。
- **文档失真**：`Old8Lang.Tests/Compiler/TODO.md` 仍称"IL 测试只有 29 个文件、缺 55 个"，实际已有 138 个；`README.md` 还写着"两种模式"和已移除的 `Json` 标准库。

> 环境：macOS 27.0.1 arm64，.NET SDK 10.0.100，Debug 构建，HEAD `d0142ed3`（工作区干净，与 `origin/master` 同 SHA）。

## 4. 本次新发现（`Todo.md` 未记录，已在 Todo.md §H 登记）

### 4.1 顶层 `Assert.Equal(x, y)` 生成非法 IL（影响最大）

```bash
# 失败
printf 'Assert.Equal(8, 8)\n' > /tmp/a.old8
dotnet run --project Old8Lang.App --no-build -- -il /tmp/a.old8
# → [IL001] 无效的IL代码: Common Language Runtime detected an invalid program.

# 传满第三个参数就正常
printf 'Assert.Equal(8, 8, "msg")\n' > /tmp/b.old8   # → 编译成功

# 放进函数里也正常
printf 'func f() -> void { Assert.Equal(8, 8) }\nf()\n' > /tmp/c.old8   # → 编译成功
```

根因定位到 `Old8Lang/AST/Expression/OperationHelpers/DotOperatorILHelper.cs` 的
`GenerateAssertMethodCall`：它按 `instance.Ids.Count` 加载实参，但 `AssertHelper.AssertEqual` 的签名是
`(object expected, object actual, string? message = null)`。只传 2 个实参时既没有补 `Ldnull`，
也没有走 `StaticClassCompiler.CompileAssertMethod` 中"缺省参数补 null"的分支，于是
`call` 一个 3 参数方法却只压了 2 个值 → 栈下溢 → 无效 IL。
`Assert.True(true)` / `Assert.Equal("a","a")` 同样复现，和值类型无关。

**影响**：`Old8Lang.Tests/Compiler/**` 几乎每个用例都是
`result <- ...` + `Assert.Equal(expected, result)` 的顶层写法，所以这条缺陷是 737 失败的最大单一来源。

### 4.2 IL 实例方法读取字段返回随机值

```bash
# class M { public v:int; init(x){this.v<-x}; func field()->int { return this.v } }
m <- M(9)
PrintLine(m.ret5())    # 5      （正常）
PrintLine(m.plus(10))  # 11     （正常）
PrintLine(m.field())   # 745215808 / 636091784 / 638352 …（每次不同）
PrintLine(m.v)         # 9      （顶层读字段正常）
```

同样的类和方法在 `-f` 下输出 `9`。即：**顶层读字段 OK、方法体内读 `this.v` 生成错误 IL**，
返回未定义的栈/内存值。`m.field()` 在函数内被调用时同样返回垃圾值（排除调用点因素）。
这与矩阵中"基本类声明 / 字段 / 方法 ✅"矛盾，也是 `Compiler.Classes` 75 个失败的重要来源之一。

### 4.3 IL 函数无法访问顶层全局变量

```bash
cat > /tmp/g.old8 <<'EOF'
g <- 10
func f() -> int { return g + 1 }
PrintLine(f())
EOF
dotnet run --project Old8Lang.App --no-build -- -il /tmp/g.old8
# → 错误信息: 变量 'g' 未声明
```

顶层变量在 IL 里是 `OldLangRun` 的局部变量，而函数是独立的 `DynamicMethod`，编译函数体时看不到它们。
`CompilerTests/closure_global_test.old8`、`global_access_test.old8` 失败即此原因。
`MODE_SUPPORT.md` 未记录这条限制。

### 4.4 IL 模式顶层语句被执行两次

`Old8Lang/Compiler/Compiler.cs:286` 在生成 IL 之前调用
`statement.ExecuteModule(i.Manager, skipFunctionClassInit: false)`（注释写的是"预执行函数声明以支持装饰器"），
但 `ExecuteModule` 会执行**全部** `OtherStatements`（赋值、`PrintLine`、文件写入……），随后再执行编译产物。

```old8
PrintLine("A")
PrintLine(2 + 3)
PrintLine("B")
```

`-il` 输出：

```text
A
5
B
[编译信息] 编译成功
A
5
B
```

后果：IL 模式下任何带副作用的顶层代码都会执行两次；如果 IL 编译失败，副作用也已经发生。
建议预执行只保留 `FuncInit` / `ClassInit` / `ExtensionDeclaration`（即 `skipFunctionClassInit: false`
只处理声明），不要执行 `OtherStatements`。

### 4.5 IL 打印布尔值大小写不一致

`PrintLine(true)`：解释器 / VM 输出 `true`，IL 编译产物输出 `True`（走 .NET `bool.ToString()`）。
属小的跨模式行为差异，但会破坏以输出文本为准的对拍。
