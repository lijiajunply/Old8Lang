## 🔴 高优先级问题

### 1. 编译器模式核心问题修复

**优先级**：🔴 紧急
**当前状态**：编译器测试通过率只有 43.6%（489个测试中272个失败）

#### 主要问题

1. **Assert.True 等方法查找失败**
   - **错误位置**：`Operation.cs:1630`
   - **错误信息**：`方法 'True' 未找到`
   - **影响**：大量断言测试失败
   - **根本原因**：IL代码生成时方法解析问题

2. **类型检查过于严格**
   - **示例**：`VariableReassignment_DifferentTypes_CompilesAndExecutes` 测试失败
   - **错误信息**：`类型不兼容: 预期 Int32, 实际 String`
   - **问题**：动态语言应该允许变量类型改变
   - **需要调整**：放宽编译模式的类型检查，或明确类型系统设计目标

3. **IL代码生成问题**
   - 跳转语句（break/continue/return）生成失败
   - 类型转换问题
   - 方法调用解析问题

#### 建议解决方案

```csharp
// 1. 修复 Assert.True 方法查找
// 在 Operation.cs 中确保正确查找 System.Diagnostics.Debug.Assert 或自定义 Assert 类

// 2. 调整类型检查策略
// 在 LocalManager.cs 中添加配置选项
public bool StrictTypeChecking { get; set; } = false; // 默认宽松模式

// 3. 完善方法解析逻辑
// 在方法调用时考虑方法重载、隐式转换等
```

#### 预期结果

- 编译器测试通过率从 43.6% 提升到 **90%+**
- 用户可以正常使用编译模式
- 编译模式和解释模式行为一致

### 3. 类型系统统一与完善

**优先级**：🔴 重要
**当前状态**：类型推断默认禁用，编译器和解释器行为不一致

#### 当前问题

| 特性 | 解释器模式 | 编译器模式 | 问题 |
|-----|----------|-----------|------|
| 函数参数类型 | 可选 | **必需**（或默认值） | ❌ 不一致 |
| 函数返回类型 | 可选（推断） | **必需** | ❌ 不一致 |
| 变量类型改变 | ✅ 允许 | ❌ 不允许 | ❌ 不一致 |
| Lambda参数类型 | 可选 | **必需** | ❌ 不一致 |
| 类型推断 | ✅ 启用 | ❌ 禁用 | ❌ 不一致 |

#### 根本原因

1. **类型推断系统默认禁用**
   ```csharp
   // TypeInferenceConfig.cs
   public bool EnableTypeInference { get; set; } = false; // ⚠️ 默认关闭
   ```

2. **编译器模式限制过于严格**
   - 为了生成正确的 IL 代码，要求所有类型明确
   - 但这与动态语言特性相悖

3. **类型检查逻辑不统一**
   - 解释器运行时类型检查
   - 编译器静态类型检查
   - 两者规则不同

#### 建议解决方案

**方案A：默认启用类型推断（推荐）**
```csharp
// 1. 修改 TypeInferenceConfig.cs
public bool EnableTypeInference { get; set; } = true; // ✅ 默认开启

// 2. 改进类型推断算法
// - 支持从调用处推断参数类型
// - 支持泛型类型推断
// - 支持联合类型（多分支返回不同类型）

// 3. 编译器生成动态类型检查代码
// 当类型无法静态确定时，生成运行时类型检查
```

**方案B：统一类型注解要求**
```csharp
// 明确定义 Old8Lang 为可选类型注解语言
// 解释器和编译器都接受无类型注解代码
// 编译器在无法推断时使用 object 类型
```

#### 预期结果

- ✅ 解释器和编译器行为一致
- ✅ 类型推断默认启用
- ✅ 用户体验提升（减少类型注解负担）

### 11. 模式匹配增强

**优先级**：💡 新特性
**当前状态**：`MatchExpression` 部分功能未实现

#### 建议添加

```old8
// 解构匹配
match point {
    case (0, 0) -> PrintLine("Origin")
    case (x, 0) -> PrintLine($"On X-axis: {x}")
    case (0, y) -> PrintLine($"On Y-axis: {y}")
    case (x, y) -> PrintLine($"Point: ({x}, {y})")
}

// 类型匹配 + 守卫
match value {
    case x:int if x > 0 -> PrintLine("Positive int")
    case x:int if x < 0 -> PrintLine("Negative int")
    case s:string -> PrintLine($"String: {s}")
    case _ => PrintLine("Other")
}

// 范围匹配
match age {
    case [0~12] -> PrintLine("Child")
    case [13..19] -> PrintLine("Teen")
    case [20..64] -> PrintLine("Adult")
    case [65..90] -> PrintLine("Senior")
    default -> PrintLine("Invalid age")
}
```
