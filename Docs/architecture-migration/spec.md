# 架构迁移需求规格

状态：草案，2026-11-13。本文描述剩余迁移的验收目标；实施方案见 [design.md](design.md)，阶段与验证见 [plan.md](plan.md)。

## 背景与目标

Old8Lang 支持解释、IL 和字节码 VM。当前 `Old8Lang.Runtime` 仍同时包含 AST、语法解析、三种执行后端和大量内置运行时功能，节点也直接持有解释执行与 IL 生成逻辑。目标是建立可验证的单向依赖，使语法模型不依赖具体后端，宿主能够显式组合所需能力，并降低修改一种执行模式时影响其他模式的范围。

## 范围与约束

- 分离语法模型与解析、共享运行时契约、解释器、IL 后端和字节码/VM 后端；按实际依赖决定程序集边界，不以建立空项目作为完成标准。
- 保持三种模式的现有语言语义、CLI 参数、官方模块名称、字节码读取与分发行为；既有模式限制以 [MODE_SUPPORT.md](../MODE_SUPPORT.md) 为基线，不将迁移视为补齐功能。
- 宿主显式注册官方模块；分别创建的宿主及执行实例不得意外共享模块目录。必须审计默认静态注册表的剩余路径。
- 已接受 C# 源码 API 不兼容；删除旧入口前须列出受影响的公开类型、迁移方式和使用方，并更新相应文档。Old8 语言和 CLI 的可见行为不应因此变化。
- 不扩大到新语法、性能专项优化或与迁移无关的缺陷修复。无关失败按仓库规范记入 `Todo.md`。

## 当前基线

截至提交 `191ba4ba`，Core、Concurrency、Observability、ProjectSystem、模块抽象/官方装配和 Runtime 已分离；执行入口已集中，块语句的普通和生成器解释执行已迁往 Visitor。`OldStatement` / `LangExpression` 及许多具体节点仍引用解释器或 IL 类型；Visitor 也仍回调旧节点方法。因而目前并未具备独立 AST 或后端程序集。

工作区中的 `BlockStatement` / `InterpreterVisitor` 导入迁移尚未完成测试和提交；它不是已完成基线。
（该段为 `191ba4ba` 时点快照；`BlockStatement` 已在阶段 2 迁入 `Old8Lang.Syntax`，后续进展见
[plan.md](plan.md) 的进度记录。）已有报告记录 IL 数组相关失败和其他已知失败，必须先复现基线并区别迁移引入的回归。

## 验收标准

1. 语法模型与解析项目可独立构建，程序集引用及源码边界测试证明其不依赖解释器、IL、VM 或官方扩展程序集；节点不提供依赖具体后端的执行方法。
2. 三种后端可分别构建，依赖方向无循环；实际执行入口和内部调用不再依赖节点的旧 `Run`、`GenerateIl`、`LoadIlValue` 等后端方法。共享运行时值和语法节点的归属有明确边界。
3. CLI、LSP、测试及基准的组合根显式配置所需模块；两个独立宿主的模块目录隔离，覆盖解释器、编译路径与 VM，默认兼容路径的去留有测试证明。
4. 三种模式的既有功能、错误与源码位置、模块导入、闭包、类、异常、异步/生成器和 VM 字节码往返有针对性回归；默认测试档与解决方案构建结果有完整报告，失败与基线逐项对照。
5. 迁移文档、开发指南、项目引用及公开 API 迁移说明与实际代码一致；每阶段均有测试报告和独立提交，最终工作区不含本任务遗留的未提交改动。

测试通过不意味着现有所有模式功能等价；测试须验证各模式自身既有行为及明确支持的跨模式共同子集。
