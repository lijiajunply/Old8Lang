# AST节点重构计划

## 一、引入访问者模式

### 1. 设计Visitor接口
- 创建`IVisitor`接口，包含针对每种AST节点类型的`Visit`方法
- 支持双重分派机制，允许不同访问者对同一节点执行不同操作
- 保持节点结构与操作逻辑分离

### 2. 实现Accept方法
- 在`IOldLangTree`接口中添加`Accept`方法
- 在所有AST节点类中实现`Accept`方法，调用访问者对应的`Visit`方法

### 3. 示例实现
```csharp
// 访问者接口
public interface IVisitor<T>
{
    T Visit(Operation node);
    T Visit(IfStatement node);
    // 其他节点类型的Visit方法
}

// 节点基类实现
public abstract class OldExpr : IOldLangTree
{
    // 现有代码...
    
    public abstract T Accept<T>(IVisitor<T> visitor);
}

// 具体节点实现
public class Operation : OldExpr
{
    // 现有代码...
    
    public override T Accept<T>(IVisitor<T> visitor) => visitor.Visit(this);
}
```

## 二、简化节点层次结构

### 1. 分析现有节点层次
- 识别冗余的中间抽象层
- 合并功能相似的节点类型
- 消除不必要的节点继承关系

### 2. 具体优化点
- 合并`OldIf`和`IfStatement`，简化if语句节点结构
- 优化表达式节点的继承关系，减少中间层
- 简化语句节点的组合关系，提高代码可读性

### 3. 保持语义完整性
- 确保简化后的节点层次不丢失关键语法信息
- 更新相关的序列化/反序列化逻辑
- 保持与现有代码的兼容性

## 三、增强节点类型信息

### 1. 设计类型注解系统
- 为每个节点添加精确的类型注解和元数据
- 包括数据类型、作用域信息、类型约束和可能的类型转换规则

### 2. 实现类型信息管理
- 在节点创建时正确初始化类型信息
- 在节点操作过程中保持类型一致性
- 支持类型信息的动态更新

### 3. 类型信息应用
- 支持代码生成阶段的类型检查
- 支持优化阶段的类型驱动优化策略
- 增强错误信息的准确性和有用性

## 四、重构步骤

1. **设计并实现访问者模式**：
   - 创建`IVisitor`接口
   - 在所有节点中添加`Accept`方法
   - 实现示例访问者

2. **简化节点层次结构**：
   - 分析并合并冗余节点
   - 优化继承关系
   - 更新相关代码

3. **增强节点类型信息**：
   - 添加类型注解字段
   - 实现类型信息初始化和更新逻辑
   - 应用类型信息到代码生成和优化

4. **测试和验证**：
   - 运行现有测试用例，确保功能正常
   - 添加新的测试用例，验证重构后的功能
   - 性能测试，确保重构不影响性能

5. **文档更新**：
   - 更新AST节点文档
   - 提供访问者模式使用指南
   - 记录重构过程和决策

## 五、预期效果

- 提高AST节点的可访问性和可扩展性
- 简化节点层次结构，提高代码可读性和维护性
- 增强节点类型信息，支持更好的代码生成和优化
- 保持与现有代码的兼容性
- 为后续功能扩展奠定良好基础
