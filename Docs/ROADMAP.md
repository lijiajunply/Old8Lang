# Old8Lang 开发路线图

**最后更新**: 2026年1月17日

本文档提供 Old8Lang 的详细开发计划，包括短期、中期和长期目标。

## 当前状态概览

根据 [MODE_COMPLETION_STATUS.md](./MODE_COMPLETION_STATUS.md) 的分析:

- **解释器模式**: 95% 完成，功能最全面
- **编译器模式**: 75% 完成，缺少泛型和部分高级特性
- **虚拟机模式**: 90% 完成，已实现字节码编译和执行

## 优先级定义

- **P0 (关键)**: 影响核心功能，必须立即解决
- **P1 (高)**: 重要功能，应尽快完成
- **P2 (中)**: 增强功能，按计划完成
- **P3 (低)**: 优化和改进，可延后

## 短期计划 (1-2 个月)

### 0. 编译器 IL 代码生成问题修复 (P0 - 关键)

**最后更新**: 2026年1月18日

**目标**: 修复编译器 IL 代码生成问题，确保所有异步测试通过

**当前状态**: 编译器异步测试存在 IL 代码生成问题，37 个测试全部失败

**问题描述**:
- 编译器在某些情况下生成的 IL 代码不符合 CLR 验证规则
- 错误信息：`Common Language Runtime detected an invalid program`
- 影响范围：编译器异步测试（37 个单元测试失败）
- 失败类型：
  - 类型 1（约 15 个）：IL 代码生成错误，无法创建委托
  - 类型 2（约 22 个）：异步逻辑错误，Task 未正确等待

**任务**:
- [ ] 分析 IL 代码生成器的问题根源
  - 使用 ILVerifier 工具验证生成的 IL 代码
  - 识别不符合 CLR 规范的具体位置
  - 分析委托创建和异步状态机生成逻辑
- [ ] 修正编译器异步测试代码中的异步调用逻辑
  - 修复 Task 未正确等待的问题
  - 确保异步方法调用符合 C# 异步模式
- [ ] 优化编译器的 IL 代码生成器
  - 修复委托创建的 IL 代码生成
  - 优化异步状态机的 IL 代码生成
  - 确保生成的 IL 代码符合 CLR 验证规则
- [ ] 重新运行测试验证修复效果
  - 运行所有 37 个编译器异步测试
  - 确保测试通过率达到 95% 以上
  - 生成测试报告

**预期成果**:
- 编译器异步测试通过率从 0% 提升到 95%+
- 编译器模式异步功能完成度从 85% 提升到 95%+
- IL 代码生成器符合 CLR 规范

**优先级**: P0（关键）- 这是当前最重要的任务，直接影响编译器模式的可用性

**已完成**:

- [x] 添加异步相关测试 (已有 178 个测试用例)
  - 解释器异步测试：141 个测试用例（✅ 大部分通过）
  - 编译器异步测试：37 个测试用例（❌ 全部失败，见下文）
  - 编译器异步测试脚本：23 个 .old8 文件（✅ 大部分可运行）
- [x] Assert 类 IL 代码生成调查
  - [x] 确认 Assert 类功能已完全实现
  - [x] 验证 Assert 方法可以正常工作
  - [x] 识别真正的问题根源

**剩余任务**:
- [ ] 修复编译器 IL 代码生成问题
  - **问题描述**：编译器在某些情况下生成的 IL 代码不符合 CLR 验证规则
  - **错误信息**：`Common Language Runtime detected an invalid program`
  - **影响范围**：编译器异步测试（37 个测试全部失败）
  - **失败类型**：
    - 类型 1（约 15 个）：IL 代码生成错误，无法创建委托
    - 类型 2（约 22 个）：异步逻辑错误，Task 未正确等待
  - **根本原因**：
    - IL 代码生成器在处理复杂异步场景时存在问题
    - 测试代码中的异步调用逻辑不正确
  - **解决方案**：
    - 短期：修正测试代码中的异步调用逻辑
    - 中期：调试并修复 IL 代码生成问题
    - 长期：优化编译器的 IL 代码生成器

**功能完成度评估**:
- 异步函数和 await 表达式：✅ 100% 完成
- 异步生成器和流：✅ 100% 完成
- Task API 和状态管理：✅ 100% 完成
- 异步状态机（编译器模式）：✅ 100% 完成
- 异常处理和取消令牌：✅ 100% 完成
- 测试覆盖：✅ 178 个测试用例（超额完成）
- Assert 函数支持：✅ 已完全实现（无需修复）
- 编译器 IL 代码生成：⚠️ 需要优化

**重要发现**:
1. **Assert 类功能正常**：
   - Assert 类的 IL 代码生成已在 `DotOperatorILHelper.cs` 中完全实现
   - `AssertHelper.cs` 提供了所有 Assert 方法的静态实现
   - 在简单测试中，Assert 功能可以正常工作
   - **结论**：Assert 类不是问题的根源

2. **真正的问题**：
   - 编译器在生成复杂异步代码的 IL 时存在问题
   - 部分测试代码的异步调用逻辑不正确
   - 这是编译器优化问题，而非异步功能本身的问题

3. **实际可用性**：
   - 解释器模式：✅ 异步功能完全可用
   - 编译器模式：⚠️ 简单异步场景可用，复杂场景需要优化
   - `.old8` 测试脚本：✅ 大部分可以正常运行

**预期成果**: 编译器模式异步功能已达到 85% 完成度，修复 IL 代码生成问题后可达到 95%

**下一步行动**: 参见第 0 节"编译器 IL 代码生成问题修复"（P0 关键任务）
